Linux 系统管理核心知识：日志管理与定时计划任务

第一部分：日志管理（Log Management）

日志是系统的“黑匣子”，记录系统运行细节，是问题排查、安全审计、性能监控和任务执行验证的关键依据，贯穿系统运维全流程。

一、日志基础：作用、服务与关键文件

（一）日志的核心作用

  1. 任务执行验证：查看定时计划任务（如crontab）执行频率，例如验证任务是否按“每分钟一次”设定运行。
  2. 异常排查定位：服务启动失败（如sshd配置错误）或系统异常时，日志精确提示错误位置（如“/etc/ssh/sshd_config第112行配置错误”），Linux 7+版本提示更详细。
  3. 非工作时段追溯：服务器24小时运行，日志记录工作人员离线期间的报错、警告，补充远程连接时本地显示器无法呈现的故障细节。
  4. 安全审计与性能监控：追踪用户登录、文件访问、系统调用（如secure日志记录暴力破解IP），长期分析日志识别系统瓶颈与资源使用趋势。

（二）Linux 核心日志服务

Linux 7/8/9版本中，日志由两类服务协同处理，功能与存储特点差异显著：

服务名称启动时机存储方式核心特点适用场景
systemd-journald随系统启动默认内存（/run/log/journal/）收集内核和早期系统日志，重启后日志丢失；可通过配置实现持久化查看系统启动初期临时日志
syslog（视频口误提及）随内核启动默认内存记录系统启动早期日志，临时性存储，重启后旧日志丢失；可改持久化辅助查看启动初期日志
rsyslog系统运行中持续工作默认磁盘（/var/log/）接收journald及应用日志，永久存储，支持自定义存储规则，功能更强大长期保存、查询各类系统/服务日志

（三）/var/log 目录下的关键日志文件

日志文件核心用途查看/操作要点
messages通用日志，记录除mail、authpriv、cron外的大部分系统消息排除重复类别，避免有效信息淹没；可通过rsyslog配置查看排除规则
secure安全日志，记录用户登录（成功/失败）、sudo操作、useradd等权限相关行为grep "failed password" /var/log/secure定位暴力破解IP；chattr +a防篡改
cron定时任务日志，记录crontab任务执行情况格式：“时间+主机名+进程名+事件”；vi中按大写“G”跳转最新记录
wtmp/btmp二进制日志，分别记录登录历史、登录失败历史无法vi直接查看；last读wtmp，lastb读btmp；二进制格式防篡改、省资源
dmesg内核消息缓冲区日志，含硬件检测、内核模块加载信息可通过dmesg命令直接查看，或查看/var/log/dmesg文件

二、日志查看与故障排查实操

（一）基础查看与实时监控命令

  1. 实时跟踪日志：tail -f /var/log/[文件名]（如tail -f /var/log/secure），实时捕捉新产生的登录、用户创建等日志。
  2. 关键词过滤：grep [关键词] /var/log/[文件名]（如grep "useradd" /var/log/secure），快速定位目标记录。
  3. 关键信息提取与统计：
    • 截取IP地址：grep "Failed password" /var/log/secure | awk '{print $11}'
    • 统计重复IP（判断暴力破解）：grep "Failed password" /var/log/secure | awk '{print $11}' | sort | uniq -c | sort -nr
  4. 时间范围查找：sed -n '/2025-11-27 11:00:00/,/2025-11-27 14:00:00/p' /var/log/messages，精准筛选时段日志。

（二）journalctl 工具：高级日志筛选与查看

journalctl是systemd系统中查询journald日志的核心工具，支持多维度组合筛选，功能灵活。

选项/用法功能描述示例
按日志类型筛选
journalctl --system查看系统级日志，默认时间由远及近显示搭配-e直接跳转最新日志（最后一页），向上翻页查更早内容
journalctl --user查看当前用户日志，默认无记录，结果为空-
journalctl -k/--dmesg仅查看内核日志，与--system结果部分重复（--system含内核日志）journalctl -k专注内核，排除系统其他日志干扰
排序与显示方式
journalctl -r时间由近及远倒序显示，最上方为最新日志需向下翻页查更早内容，区别于-e的“直接看最后一页”
journalctl -f实时跟踪新日志，类似tail -fjournalctl -fu sshd.service实时监控sshd服务日志
按条件精准筛选
journalctl -p [级别]查看指定级别及更严重日志（包含关系：级别从轻到重：debug→info→notice→warning→err→crit→alert→emerg）journalctl -p err显示err及以上；-p warning含err、emerg等
journalctl --since/--until "时间"按时间范围筛选，格式“年月日 时分秒”（秒可省），支持“最近一小时”等描述journalctl --since "2025-11-27 11:30" --until "2025-11-27 14:00"
journalctl _PID=[进程号]查看指定进程日志，需进程持续存在且有日志产生进程重启后PID变化，旧日志需用旧PID查询（如sshd原PID 11930）
journalctl -u [服务名]仅查看指定服务日志，排除其他干扰journalctl -xeu sshd.service：-x加解释信息，定位服务启动失败原因
高级操作
journalctl --disk-usage查看日志占用存储空间虚拟机中默认约5.9MB，需维持基础大小，过大时再清理
journalctl --vacuum-size/--vacuum-time清理日志，限制留存大小或时间journalctl --vacuum-size=100M；--vacuum-time=1week

三、日志管理核心操作

（一）日志轮替（Log Rotation）：防止文件过大

通过周期性处理旧日志、创建新日志，避免单个文件无限增大，保证日志可查性，依赖系统默认工具logrotate。

  1. 轮替触发条件：

    • 时间周期：daily/weekly/monthly，适合日志生成量稳定场景；
    • 大小周期：size 200KB/100M，达到指定大小触发，适合生成量不稳定场景。

  2. 配置文件与优先级：

    • 主配置文件：/etc/logrotate.conf（全局规则，如默认每周轮替、保存4份旧日志）；
    • 局部配置目录：/etc/logrotate.d/（为nginx、mysql等服务配置独立规则，优先级高于全局）。

  3. 关键配置项：

    配置项功能描述
    rotate 4保留4份旧日志，超过则删除最旧的
    compress轮替后压缩旧日志（可配置“不压缩最近1份”方便查看）
    create 0640 root root创建新空日志，指定权限（0640）和所有者（root:root）
    delaycompress延迟压缩，下一次轮替时再压缩当前旧日志

  4. 特殊处理与强制轮替：

    • 若日志设a属性（不可修改）：轮替前chattr -a 文件名取消属性，轮替后chattr +a恢复；
    • 强制轮替（测试规则）：logrotate -vf /etc/logrotate.d/nginx（-v详细输出，-f强制执行）。

（二）日志拆分与合并：处理已过大日志

  1. 拆分操作：用split命令拆分文本类日志（二进制文件不适用），核心选项-b指定单文件大小。
    示例：split -b 500M -d -a 3 large.log log_part_

    • -d：数字后缀；-a 3：后缀3位（000/001…）；生成log_part_000（500M）、log_part_001等。

  2. 合并操作：用cat合并拆分文件，内容与原文件一致。
    示例：cat log_part_* > large.log.restored。

（三）journal 日志持久化配置

默认journal日志存于内存，重启丢失，需配置持久化保存至磁盘：

  1. 创建目录：mkdir /var/log/journal；

  2. 重启系统：系统自动配置权限（添加sgid、所属组改为systemd-journal、设置ACL权限），无需手动操作；

  3. 存储特点：日志保存为/var/log/journal/下的二进制文件（如system.journal），无法像文本文档直接打开编辑；

  4. 用户日志隔离：系统按用户UID（如1001）在/var/log/journal/下单独创建日志文件，普通用户查看的日志更少。

  5. 限制日志大小：

    • 编辑配置文件：journald.conf（路径通常为/etc/systemd/journald.conf）；
    • 设置参数：SystemMaxUse=500M（最大占用空间）、MaxFileSize=50M（单个文件最大大小）；
    • 生效方式：重启systemd-journald服务：systemctl restart systemd-journald。

（四）日志空间管理与安全维护

  1. 日志清空方式：

    • 覆盖清空：> /var/log/[文件名]，保留inode号，避免进程因inode变化无法写入；
    • 删除重建：rm /var/log/[文件名] && touch /var/log/[文件名]，可能改变inode，多进程场景慎用。

  2. 日志防篡改：用chattr +a /var/log/[文件名]添加“仅追加”属性，文件仅允许新增内容，无法删除（rm -rf无效）、修改旧内容；lsattr /var/log/[文件名]查看属性是否生效。

四、日志集中管理：多服务器场景

（一）核心目的

多服务器环境中，将所有日志集中到“日志收集服务器”，管理员无需逐台登录，统一查看与分析。

（二）实现原理（rsyslog 客户端-服务器架构）

  1. 服务器端配置：

    • 修改/etc/rsyslog.conf：取消TCP/UDP监听端口（默认514）的注释（如$ModLoad imtcp、$InputTCPServerRun 514）；
    • 重启服务：systemctl restart rsyslog；
    • 开放端口：防火墙开放514端口（或临时关闭防火墙：systemctl stop firewalld）。

  2. 客户端配置：

    • 修改主机名：hostnamectl set-hostname A1（避免多客户端主机名重复导致日志混淆）；
    • 修改/etc/rsyslog.conf：添加发送规则，*.* @@192.168.5.144:514（@@TCP协议，@UDP协议；192.168.5.144为服务器IP）；
    • 重启服务：systemctl restart rsyslog，关闭客户端防火墙（或开放端口）。

  3. 效果验证：客户端执行useradd xe，服务器端在/var/log/messages中可看到含客户端主机名（A1）的操作记录。

五、日志配置与服务管理

（一）rsyslog 配置文件详解

  1. 核心配置文件：/etc/rsyslog.conf，规则格式为facility.priority action（类别.级别 处理方式）。

    • 类别（facility）：日志来源，如kern（内核）、cron（定时任务）、mail（邮件）、authpriv（安全）；
    • 级别（priority）：从轻到重为debug→info→notice→warning→err→crit→alert→emerg；
    • 处理方式（action）：保存文件（/var/log/xxx）、发送远程服务器（@@ip:port）、广播（*）。

  2. 经典规则示例：

    • *.info;mail.none;authpriv.none;cron.none /var/log/messages：记录所有类别info及以上日志，排除mail、authpriv、cron，保存至messages；
    • *.emerg *：所有类别emerg级别日志，广播给所有在线用户。

  3. 配置生效与自定义日志：

    • 生效方式：修改后需重启rsyslog（systemctl restart rsyslog）或重启系统；发送HUP信号（kill -HUP 进程号）无效，因rsyslog未定义该信号响应；
    • 自定义日志：添加规则*.* /var/log/my.log，所有日志保存至/var/log/my.log，重启服务后生效。

（二）systemd-journald 服务操作注意事项

  1. 命令补全：执行systemctl status systemd-journald时，系统默认补全.service后缀，无需手动添加；
  2. 服务名正确性：避免漏写“d”（如误写system-journal），否则提示“服务未找到”；
  3. 选项组合使用：支持多选项搭配，如journalctl -u sshd.service --since "2025-11-27 14:00" --until "2025-11-27 15:00"，筛选sshd服务在指定时段的日志。

第二部分：定时计划任务（Cron Jobs）

定时任务是Linux自动化运维的核心，实现命令/脚本在指定时间自动执行，核心工具为at（一次性）和crontab（周期性）。

一、核心工具对比

工具执行特性核心用途依赖守护进程适用场景
at一次性执行突发、单次任务（如10分钟后执行脚本）atd临时自动化需求，无需重复执行
crontab周期性执行重复、规律任务（如每天凌晨备份）crond日常运维自动化（备份、清理）

二、at 命令：一次性任务

（一）安装与启动

  1. 安装：sudo dnf install at（RHEL/CentOS）或sudo apt install at（Debian/Ubuntu）；
  2. 启动服务：sudo systemctl start atd；
  3. 开机自启：sudo systemctl enable atd。

（二）使用方法

  1. 交互模式：手动输入任务，按Ctrl+D提交。

    1
2
3

    at 14:30  # 设定14:30执行
at> /home/user/script.sh  # 任务内容（执行脚本）
at> <EOT>  # Ctrl+D提交

  2. 非交互模式：通过管道传递任务，适合脚本集成。

    1

    echo "/home/user/script.sh" | at now + 10 minutes  # 10分钟后执行

  3. 常用时间格式：

    • 绝对时间：at 10:00 2024-12-31（2024年12月31日10点）；
    • 相对时间：at now + 3 hours（3小时后）、at 5pm tomorrow（明天17点）。

（三）任务管理

命令功能描述
atq/at -l列出当前用户的所有待执行任务
`at -c [任务号]查看指定任务的详细内容
atrm [任务号]/at -r [任务号]删除指定任务

三、crontab 命令：周期性任务

（一）crond 服务基础

  • 默认开机自启，查看状态：systemctl status crond；
  • 服务异常时重启：systemctl restart crond。

（二）crontab 文件格式

1

3

* * * * * /path/to/command
- - - - -
| | | | |
| | | | +----- 星期（0-6，星期日=0或7）
| | | +------- 月份（1-12）
| | +--------- 日期（1-31）
| +----------- 小时（0-23）
+------------- 分钟（0-59）

  1. 特殊字符含义：

    • *：匹配所有值（如小时位*表示每小时）；
    • ,：指定多个值（如1,3,5表示1、3、5）；
    • -：指定范围（如1-5表示1到5）；
    • /：指定步长（如*/10在分钟位表示每10分钟）。

  2. 经典任务示例：

    • 0 2 * * * /usr/bin/backup.sh：每天凌晨2点执行备份脚本；
    • */15 * * * * /usr/bin/clean_temp.sh：每15分钟清理临时文件；
    • 30 22 * * 1-5 /usr/bin/echo "Good night!"：每周一至周五22:30输出提示；
    • 0 12 1 * * /usr/bin/send_report.sh：每月1日12点发送报告。

（三）crontab 命令操作

命令功能描述
crontab -e编辑当前用户的定时任务（默认用vi打开，按Esc+:wq保存退出）
crontab -l列出当前用户的所有定时任务
crontab -r删除当前用户的所有定时任务（慎用，无确认步骤）
sudo crontab -u [用户名] -e编辑指定用户的定时任务（仅root权限可用，如sudo crontab -u xe -e）

（四）系统级 cron 任务

  1. 全局配置文件：/etc/crontab，格式需额外指定执行用户，示例：
    0 2 * * * root /usr/bin/backup.sh（root用户每天2点执行备份）；
  2. 独立任务目录：/etc/cron.d/，存放系统级任务文件（如nginx定时任务）；
  3. 按频率自动执行目录：/etc/cron.hourly/（每小时）、/etc/cron.daily/（每天）、/etc/cron.weekly/（每周）、/etc/cron.monthly/（每月），放入可执行脚本（chmod +x 脚本）即可自动执行。

四、权限控制

通过allow（白名单）和deny（黑名单）文件控制用户使用at/crontab的权限，优先级：白名单 > 黑名单。

文件路径类型功能描述
/etc/at.deny黑名单列出的用户禁止使用at，默认空文件（所有用户可使用）
/etc/cron.deny黑名单列出的用户禁止使用crontab，默认空文件（所有用户可使用）
/etc/at.allow白名单仅列出的用户可使用at，默认不存在，需手动创建（优先级高于at.deny）
/etc/cron.allow白名单仅列出的用户可使用crontab，默认不存在，需手动创建（优先级高于cron.deny）

注意：若白名单存在，黑名单自动失效；建议仅在严格权限控制场景创建白名单。

五、注意事项与排错

  1. 环境变量问题：cron执行环境精简，PATH等变量与用户登录时不同，务必使用绝对路径（如/usr/bin/ls而非ls），或在脚本开头定义PATH（export PATH=/usr/local/sbin:/usr/local/bin:/sbin:/bin:/usr/sbin:/usr/bin）。

  2. 脚本权限：确保crontab调用的脚本有可执行权限：chmod +x /path/to/script.sh。

  3. 输出重定向：cron的stdout（标准输出）和stderr（标准错误）默认通过邮件发送给执行用户，易造成邮件轰炸或信息丢失，建议重定向到日志文件：

    1

    * * * * * /path/to/script.sh > /var/log/my_cron.log 2>&1  # 2>&1将错误输出合并到标准输出

  4. 日志排查：cron执行情况记录在系统日志中，通过以下命令排查任务是否执行：

    • RHEL/CentOS：grep CRON /var/log/messages；
    • Debian/Ubuntu：grep CRON /var/log/syslog。

第三部分：学习进度与建议

一、进度规划

  1. 当日任务：完成日志管理核心操作（轮替、持久化、集中管理）、journalctl详解、定时任务基础用法讲解；
  2. 次日（周五）：讲解剩余日志配置细节与定时任务进阶案例，完成本阶段全部知识点；
  3. 练习安排：周五晚上练习“服务管理（systemctl）”“系统管理（日志清理、权限配置）”，周末启动全面复习。

二、学习要求与提示

  1. 核心目标：无需死记所有命令选项，重点理解“日志轮替/集中管理/持久化”“定时任务周期逻辑”的原理；能根据日志路径/配置文件识别轮替规则，通过journalctl/cron日志定位问题。

  2. 后续难度提示：当前为基础阶段，后续还有3-4个阶段，难度递增（如“命令写文件”“网络服务配置”）；若当前基础不扎实，后续排查网络服务错误、理解复杂命令（如qpqqr）会更困难，需及时记忆细节（如日志级别、crontab格式）。

  3. 复习心态：复习中发现知识漏洞（如配置项含义遗忘）是正常现象，需通过“实操+复盘”强化记忆；时间不充裕，建议每日花30分钟整理当天命令示例，避免堆积问题。
