一、课程整体框架与学习要求

（一）课程阶段划分

当前课程分为两大核心阶段，总时长约5周，具体安排如下：

  1. 第一阶段：少儿编程与基础操作
    先进行6天Shell编程基础学习，包含脚本编写、命令使用等内容，阶段结束后进行小测；
  2. 第二阶段：网络服务深入学习
    持续约3周4-5天，围绕各类网络服务的搭建、配置与优化展开；
  3. 阶段考核形式
    每个阶段结束后均采用“笔试+机试”模式，机试时长为5小时，后续集群服务阶段考核形式一致，机试可能持续至下午3点半。

（二）学习核心要求

  1. 目标与笔记管理
    • 需制定短期目标（如每周掌握对应服务知识），确保学习节奏清晰；
    • 强调电子笔记的重要性，要求包含“步骤+截图”，每个服务学习后需提交笔记，后续工作中可复用；
  2. 练习与测试安排
    • 每周有计时周练习，需练至满分以巩固知识点；
    • 每两周安排一次周测，具体时间视学习进度调整。

二、Shell编程与操作基础

（一）编程语言分类与Shell脚本基础

  1. 编程语言分类

    • 编译性语言：
      • 特点：需先编译为中间语言，再转机器语言；
      • 代表语言：C、C++、Java、Go；
      • 执行依赖：编译器（如GCC）；
    • 解释性语言：
      • 特点：逐行读取并翻译为机器语言，源代码即脚本；
      • 代表语言：Shell、PHP、Python；
      • 执行依赖：解释器（如Bash）。

  2. Shell脚本编写与运行

    • 核心概念：Shell是Linux终端交互工具，Shell脚本需依赖Bash解释器（路径通常在/etc/shells）；
    • 编写步骤：
      1. 新建以.sh为后缀的文件（后缀仅为标识，无强制要求）；
      2. 首行固定写#!/bin/bash，指定Bash为解释器；
      3. 编写具体命令（如echo输出命令、循环语句等）；
    • 运行方式：
      1. 直接运行：bash 脚本名（无需执行权限）；
      2. 授权后运行：先通过chmod +x 脚本名添加执行权限，再用./脚本名（相对路径）或绝对路径运行。

（二）核心命令：echo

  1. 输出格式控制

    • 换行控制：加-n选项可实现不换行输出（如echo -n "请输入姓名："），默认情况下输出后自动换行；
    • 特殊字符识别：加-e选项可识别反斜线（\）开头的特殊字符，常用如下：
      • \a：
        • 功能描述：输出系统警告音；
        • 示例：echo -e "警告\a"；
      • \b：
        • 功能描述：回退并删除一个字符（需后续有字符）；
        • 示例：echo -e "hel\blo"（输出“hlo”）；
      • \t：
        • 功能描述：插入制表符（约4个空格）；
        • 示例：echo -e "姓名\t年龄"；
      • \n：
        • 功能描述：插入换行符，强制换行；
        • 示例：echo -e "第一行\n第二行"；
      • \f：
        • 功能描述：插入换页符，换行后保留前方缩进；
        • 示例：echo -e "标题\f内容"。c

  2. 输出颜色与特殊效果设置

    • 颜色代码规则：借助-e选项，通过\e[颜色代码m设置，结束颜色需加\e[0m（取消所有设置）；
    • 常用颜色代码：
      • 黑色：
        • 字体颜色代码：30；
        • 背景颜色代码：40；
      • 红色：
        • 字体颜色代码：31；
        • 背景颜色代码：41；
      • 绿色：
        • 字体颜色代码：32；
        • 背景颜色代码：42；
      • 黄色：
        • 字体颜色代码：33；
        • 背景颜色代码：43；
      • 蓝色：
        • 字体颜色代码：34；
        • 背景颜色代码：44；
      • 紫色：
        • 字体颜色代码：35；
        • 背景颜色代码：45；
      • 青色：
        • 字体颜色代码：36；
        • 背景颜色代码：46；
      • 白色：
        • 字体颜色代码：37；
        • 背景颜色代码：47；
    • 特殊效果代码：1（高亮）、4（下划线）、5（闪烁）、7（反显）、8（消隐），可与颜色组合（如echo -e "\e[1;32m高亮绿色\e[0m"）。

  3. 练习题与优化

    • 基础需求：用脚本打印8种颜色的“hello”，初始可编写8条echo命令实现；
    • 优化方案：利用for循环遍历颜色代码，减少重复代码（如for color in 30 31 32; do echo -e "\e[${color}mhello\e[0m"; done）.

（三）Shell循环：for循环

  1. 基本语法与执行逻辑

    • 语法格式：for 变量名 in 取值列表; do 循环体; done（变量名常用i，可自定义）；
    • 执行逻辑：取值列表中的值依次赋给变量，每次赋值后执行一次循环体，循环次数等于取值列表中值的个数；
    • 取值列表类型：
      • 具体字符/字符串：
        • 示例：for i in a b c; do echo $i; done；
        • 输出结果：a、b、c；
      • 数字序列：
        • 示例：for i in 1 2 3; do echo $i; done；
        • 输出结果：1、2、3；
      • 数字序列（简写）：
        • 示例：for i in {1..3}; do echo $i; done；
        • 输出结果：1、2、3；
      • 通配符匹配：
        • 示例：for i in *.sh; do echo $i; done；
        • 输出结果：当前目录下所有.sh文件。

  2. 变量取值与输出

    • 输出变量需用$变量名（如echo $i），若变量后紧跟其他字符，需用${变量名}隔离（如echo ${i}file，避免变量与字符混淆）。

（四）Shell操作效率工具

  1. 常用快捷键（提升终端操作速度）

    • Ctrl + l：等同于clear，清空终端屏幕；
    • Ctrl + d：类似exit，退出当前终端会话；
    • Ctrl + c：中断当前执行的命令（如中断持续连接、进程）；
    • Ctrl + z：将当前命令暂停并放入后台（状态为暂停）；
    • 命令后加&：将命令主动放入后台运行（非暂停，持续执行）；
    • Ctrl + a：光标快速移动到当前命令开头；
    • Ctrl + e：光标快速移动到当前命令结尾；
    • Ctrl + s：停止控制台输出（非Windows的“保存”，需注意）；
    • Ctrl + q：解锁Ctrl + s暂停的控制台输出，恢复显示；
    • Ctrl + r：搜索命令历史记录，输入关键词匹配过往命令；
    • Ctrl + u：剪切当前光标之前的命令内容；
    • Ctrl + k：剪切当前光标之后的命令内容；
    • Ctrl + y：粘贴被Ctrl + u/Ctrl + k剪切的内容；
    • 注意：不建议修改默认快捷键，避免操作习惯混乱，通过练习可逐步熟悉。

  2. 历史命令（history）

    • 核心功能：查看当前终端执行过的命令，支持回顾操作、重复调用、调试错误；
    • 调用方式：
      • !命令编号：
        • 功能描述：调用对应编号的历史命令；
        • 示例：!100（调用第100条命令）；
      • !!：
        • 功能描述：调用最近一条历史命令；
        • 示例：!!（重复上一条命令）；
      • !命令开头字符：
        • 功能描述：调用最近一条以该字符开头的命令；
        • 示例：!ls（调用最近一条ls命令）；
    • 存储与加载：
      • 默认仅记录当前终端命令，不同终端独立；
      • 终端正常退出（exit、Ctrl + d、重启、logout、reboot）时，历史命令写入用户家目录.bash_history隐藏文件；
      • 重新登录时，系统从.bash_history加载命令到history变量；
    • 清理与手动写入：
      • history -c：清空当前history变量中的命令（不删除.bash_history，重新登录后恢复）；
      • 彻底清空需手动删除.bash_history文件；
      • 手动写入：无需退出，可通过操作将当前history变量中的命令写入.bash_history。

  3. Tab补全功能

    • 作用：补全文件名、目录名、命令名、命令选项，输入部分内容后按Tab键即可；
    • 特殊场景：若有多个匹配项，按两次Tab键可显示所有匹配内容，供选择后继续补全；
    • 优势：减少输入错误，提升效率（尤其适用于长文件名、复杂命令）。

  4. 别名（alias）

    • 基本操作：
      • 查看别名：
        • 命令/语法：alias（直接执行）；
        • 示例：alias（显示当前所有别名，如ls='ls --color=auto'）；
      • 创建别名：
        • 命令/语法：alias 别名="原命令及选项"；
        • 示例：alias cl="clear"（输入cl等同于clear）；
      • 修改别名：
        • 命令/语法：重新执行alias命令覆盖原定义；
        • 示例：alias cl="clear; echo 已清空"（修改cl功能）；
      • 删除别名：
        • 命令/语法：unalias 别名；
        • 示例：unalias cl（删除cl别名）；
    • 临时性与永久性：
      • 临时别名：直接在终端创建，终端退出后失效；
      • 永久别名：需写入配置文件，~/.bashrc（仅当前用户）或/etc/bashrc（所有用户）；
      • 生效方式：写入配置文件后，需重新登录终端或执行source 配置文件路径（如source ~/.bashrc）加载。

  5. 配置文件加载与source命令

    • source命令功能：重新加载配置文件，使修改在当前终端立即生效（无需重新登录），也可用.代替（如. ~/.bashrc等同于source ~/.bashrc）；
    • 适用场景：仅用于加载包含Shell命令、环境变量的脚本类配置文件（如.bashrc、/etc/bashrc）；
    • 不适用场景：网卡配置文件、SSH服务配置文件等非脚本类文件，需重启对应服务或系统生效。

  6. 命令优先级（执行顺序）

    • 优先级1：
      • 命令类型：绝对路径指定的命令；
      • 示例：/bin/ls；
    • 优先级2：
      • 命令类型：别名（匹配已定义的别名）；
      • 示例：cl（对应clear命令）；
    • 优先级3：
      • 命令类型：内部命令（Shell内置命令）；
      • 示例：cd、echo；
    • 优先级4：
      • 命令类型：外部命令（PATH环境变量指定目录中查找）；
      • 示例：ls（在/usr/bin中查找）；
    • PATH环境变量：存储系统查找外部命令的目录列表，目录间用冒号分隔，可通过echo $PATH查看（如/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin）；
    • 自定义命令：将自定义命令所在目录添加到PATH，可实现直接执行（需确保命令有可执行权限）。

三、输入输出重定向与自定义内容写入

（一）基础概念与文件描述符

  • 核心设备与描述符：
    • 标准输入（STDIN）：
      • 对应设备：键盘；
      • 文件描述符：0；
      • 功能描述：接收用户输入数据；
      • 示例场景：修改密码时输入密码；
    • 标准输出（STDOUT）：
      • 对应设备：终端/显示器；
      • 文件描述符：1；
      • 功能描述：输出命令执行的正确结果；
      • 示例场景：ls显示目录内容；
    • 标准错误输出（STDERR）：
      • 对应设备：终端/显示器；
      • 文件描述符：2；
      • 功能描述：输出命令执行的错误信息；
      • 示例场景：ls /wrongpath报错；
  • 默认行为：标准输出、标准错误输出均显示在终端，可通过重定向导向文件或“回收站”。

（二）重定向符号及功能

  • >：
    • 功能描述：覆盖式重定向标准输出（默认描述符1），文件不存在则创建，存在则清空；
    • 示例：echo 123 > 1.txt（“123”写入1.txt，覆盖原有内容）；
  • >>：
    • 功能描述：追加式重定向标准输出，在文件末尾添加内容；
    • 示例：echo 456 >> 1.txt（“456”追加到1.txt末尾）；
  • 2>：
    • 功能描述：覆盖式重定向标准错误输出，错误信息写入文件；
    • 示例：ls /wrongpath 2> error.txt（报错写入error.txt）；
  • 2>>：
    • 功能描述：追加式重定向标准错误输出；
    • 示例：ls /anotherwrong 2>> error.txt（报错追加到error.txt）；
  • &> 或 1>&2、2>&1：
    • 功能描述：&>：将标准输出和标准错误输出一起覆盖式重定向到指定文件；1>&2：标准输出导向标准错误输出；2>&1：标准错误输出导向标准输出；
    • 示例：ls /test &> all.log（正确/错误结果均写入all.log并覆盖原有内容）；
  • >/dev/null：
    • 功能描述：输出导向“回收站”设备/dev/null，丢弃内容不占空间；
    • 示例：ss -tuln > /dev/null（仅判断命令是否成功，不保留输出结果）。

（三）自定义结束符（EOF）

  1. 核心作用：向文件中写入多行复杂内容（如脚本、配置文件），无需逐行执行命令；
  2. 语法格式（以写入2.sh为例）：
    1
2
3
4
5

    cat > 2.sh << EOF
#!/bin/bash
echo "你好"
echo "当前时间：\$(date)"  # 支持变量（需转义特殊字符，如\$）
EOF
  3. 关键规则：
    • 结束符EOF可自定义（如CCC、END，需为3个字符左右）；
    • 结束符需单独成行，前后不能有多余空格，否则无法识别结束位置；
    • 支持变量和特殊字符，特殊字符需转义（如\$、\），避免被Shell提前解析。

四、Shell关键命令详解

（一）tee命令（双向输出：终端+文件）

  • 核心功能：从标准输入（键盘或管道）读取数据，同时输出到终端和指定文件，支持覆盖/追加；
  • 常用选项：-a：追加模式（默认覆盖模式）；
  • 示例（键盘输入）：tee 4.txt（输入内容后按Ctrl + c，内容同步显示在终端并写入4.txt）；
  • 示例（管道输入）：df -h | tee -a disk.log（df -h结果同步显示在终端并追加到disk.log）.

（二）wc命令（内容统计：行数/单词数/字符数）

  • 核心功能：全称为“word count”，统计文件或输入内容的行数、单词数、字符数；
  • 常用选项：-l：仅统计行数；-w：仅统计单词数（按空格分隔）；-c：仅统计字符数（含换行符）；
  • 选项示例（行数）：wc -l 1.txt（输出1.txt的行数）；
  • 选项示例（单词数）：echo "hello world" | wc -w（输出2）；
  • 选项示例（字符数）：wc -c 1.txt（输出1.txt的字符总数）；
  • 基础示例：wc 1.txt（输出格式：行数 单词数 字符数 文件名，如“5 10 60 1.txt”）。

五、多命令执行与条件判断

（一）多命令执行符号（组合执行逻辑）

  • ;：
    • 功能描述：顺序执行，命令间无依赖，前一条失败不影响后一条；
    • 示例：ls /; echo "执行完成"（无论ls /是否成功，均输出“执行完成”）；
  • &&：
    • 功能描述：逻辑“与”，前一条成功（返回值0）才执行后一条；
    • 示例：mkdir test && cd test（成功创建test后进入目录）；
  • ||：
    • 功能描述：逻辑“或”，前一条失败（返回值非0）才执行后一条；
    • 示例：mkdir test || echo "创建失败"（test已存在则提示）。

（二）test命令（条件判断基础）

  • 核心功能：测试表达式的真假，返回值0（真）或非0（假），常用于字符串、数值判断；
  • 字符串判断示例（相等）：test "abc" == "abc" && echo "相等"（判断成立，输出“相等”）；
  • 字符串判断示例（不相等）：test "abc" == "abcd" || echo "不相等"（判断不成立，输出“不相等”）；
  • 关键注意事项：判断时==前后需加空格；单个=用于变量赋值，两个==用于判断。

六、网络服务核心知识

（一）网络服务基础概念

  1. 定义：网络上运行的软件模块，提供特定功能供客户端远程访问，需通过IP定位服务器、端口定位服务、协议实现通信；
  2. 关键服务与协议/端口：
    • SSH：
      • 功能：远程登录；
      • 默认端口：22；
      • 备注：后台持续运行的进程；
    • HTTP：
      • 功能：网页服务；
      • 默认端口：80；
      • 备注：对应Apache、Nginx等软件；
    • FTP：
      • 功能：文件传输；
      • 默认端口：20（数据）、21（控制）；
      • 备注：需搭建vsftpd服务；
    • SMTP：
      • 功能：邮件发送；
      • 默认端口：25；
      • 备注：基于Postfix等软件；
    • DNS：
      • 功能：域名解析；
      • 默认端口：53（UDP/TCP）；
      • 备注：分正向解析（域名→IP）、反向解析（IP→域名）；
  3. 域名与IP：访问网站输入域名（如百度），需DNS解析为IP；不指定端口时，默认使用协议对应端口（如HTTP默认80）。

（二）网站服务架构：LAMP与LNMP

  • LAMP：
    • 组成：Linux（系统）、Apache（Web服务器）、MySQL（数据库）、PHP（语言）；
    • 核心优势：架构成熟、兼容性强，搭建简单；
    • 适用场景：中小规模网站、访问量较低的场景；
  • LNMP：
    • 组成：Linux（系统）、Nginx（Web服务器）、MySQL（数据库）、PHP（语言）；
    • 核心优势：Nginx支持更高并发量，避免单请求单对接拥堵；
    • 适用场景：用户量较大、并发量高的场景。

（三）其他核心服务与工具

  1. 数据共享与传输：
    • FTP：文件传输（需vsftpd）；
    • NFS：网络文件系统（同一局域网内共享目录）；
    • FMC等工具：辅助远程访问与数据管理；
  2. 数据备份策略：
    • 完全备份：
      • 特点：备份所有数据，占用空间大；
      • 代表命令：cp、scp；
    • 增量备份：
      • 特点：仅备份与上一次备份的差异数据，效率高；
      • 代表命令：rsync；
    • 差量备份：
      • 特点：仅备份与第一次完全备份的差异数据；
      • 代表命令：-；
  3. 数据库服务：后续将讲解MySQL（关系型数据库，存储结构化数据）与Redis（缓存数据库，提升读取速度）的搭建与使用；
  4. DHCP服务：自动分配IP地址，设备接入网络时无需手动设置IP，简化网络配置。

七、学习实践与注意事项

（一）实践案例：Apache服务状态判断

  1. 思路1：基于文件内容判断
    1
2
3
4

    # 查看80端口（HTTP默认端口），结果写入apache.log
ss -tuln | grep :80 > apache.log
# 判断文件是否非空（非空则服务已启动）
if [ -s apache.log ]; then echo "Apache已启动"; else echo "Apache未启动"; fi
  2. 思路2：基于命令返回值判断
    1
2
3
4

    # 查看80端口，输出导向回收站（仅保留返回值）
ss -tuln | grep :80 > /dev/null
# 返回值$?为0则成功（服务已启动），非0则失败
if [ $? -eq 0 ]; then echo "Apache已启动"; else echo "Apache未启动"; fi
