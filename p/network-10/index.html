4. 网络基础阶段

Tomcat 与 Web 服务反向代理

介绍《Tomcat 与 Web 服务反向代理》，涵盖核心技术概念铺垫、反向代理与负载均衡和数据库分类与特性等实践要点。

2025/12/24 · 5672 字 · -- 次阅读

一、核心技术概念铺垫

（一）反向代理与负载均衡

  1. 反向代理核心特性：具备服务器保护能力，与普通地址跳转存在本质区别；Nginx作为反向代理核心工具，常承担请求分发职责，静态资源可由Nginx直接本地高效处理，动态资源则转发至后端服务。
  2. 负载均衡相关内容：Nginx支持权重分配、最小连接数、轮询等多种负载均衡算法；对比Nginx与DNS负载均衡，Nginx在稳定性、扩展性上更具优势，可配置多个后端代理目标IP实现请求分发。
  3. 反向代理逻辑：静态项目仅需搭建Apache、Tomcat即可运行，动态项目需额外整合PHP、MySQL等服务；部署时需先确保后端服务正常，再配置Nginx代理指向对应后端机器（如指向192相关网段的minepress项目）。

（二）数据库分类与特性

  1. 分类标准：根据数据间是否存在关联关系，分为关系型数据库与非关系型数据库。
  2. 关系型数据库：以MySQL、Oracle、SQL Server为代表，采用二维表（行=数据记录、列=数据字段/表头）形式存储，数据列数与列含义统一，支持事务特性；可类比Excel，MySQL软件对应Excel程序、数据库对应Excel文件、数据表对应Excel工作簿，一个MySQL实例可包含多个数据库，一个数据库可包含多个数据表。
  3. 非关系型数据库：以Redis、MongoDB、HBase为代表，存储格式灵活多样（含键值对KV、文档型、宽列存储等），海量数据处理速度快，适用于数据关联度低的场景。
  4. 版本渊源：MySQL始于1979年，2008-2009年被Oracle收购后存在闭源风险，开发者基于MySQL 5.5版本分支开发出开源免费的MariaDB，后续两者版本号差异化发展（MySQL从8.0起步，MariaDB从10.0起步）。

二、Web服务配置实操（Nginx/Apache/Tomcat）

（一）Nginx核心配置与应用

  1. 核心功能定位：主打反向代理，处理静态资源速度优异；做反向代理时，静态资源一般由后端自身服务承载，动态资源通过代理转发至Apache/Tomcat等后端服务。
  2. 基础环境与配置校验：按需安装PHP环境；配置修改后需通过bash命令校验语法并热重启生效： 
    # 校验Nginx配置语法
nginx -t
# 热重启Nginx使配置生效
nginx -s reload
  3. 虚拟主机配置：支持基于域名的虚拟主机配置，需指定网站根目录并创建测试页验证有效性。
  4. 地址跳转配置：可设置301/302跳转规则，后续还支持HTTP自动跳转至HTTPS，确保访问安全性且保持URL不变。
  5. 动态代理配置：通过location指令针对不同后缀（如.jsp、.php）的动态请求，指定代理目标（如Apache服务器），支持配置多个后端代理目标IP。
  6. 项目代理配置：单个页面代理可通过明确页面路径配置；多页面项目代理仅需匹配项目根路径（如/MatePrice/、/WordPrice/），后续路径自动拼接，无需逐个配置页面，支持同时代理多个项目并分别指向对应后端服务。

（二）Apache（阿帕奇）相关操作

  1. 模块加载与虚拟主机配置：需加载mod_vhost_alias模块，在vhost目录下创建配置文件，通过DocumentRoot指定网页根目录（如/var/www/html），配置完成后重启服务生效。
  2. PHP环境配置与测试：
    • 在虚拟主机配置中关联PHP模块，生成对应配置文件并重启Apache服务；
    • 创建index.php测试页编写验证代码，通过访问Apache IP或域名验证PHP环境是否正常；
    • PHP作为解释性语言，报错信息会直接在页面显示，便于排查问题；
    • 验证虚拟主机可通过curl命令实现： 
      # 验证Apache虚拟主机生效
curl http://指定域名/
  3. 项目部署特性：单个页面需放置在网页根目录下，完整项目直接放入指定根目录（无需额外嵌套层级）；Apache支持自动解压部署.war、.gz等压缩格式项目包，区别于Tomcat的webapps目录部署方式。
  4. 权限基础：Apache运行时有对应的进程所有者，后续项目部署需保证该用户对项目目录有读写权限。

（三）Tomcat部署与配置

  1. 依赖环境：需先安装并验证JDK环境，确保Tomcat正常运行。
  2. 基础配置：默认监听8080端口，支持虚拟主机配置；若需修改为1024以内端口，需切换至root用户操作。
  3. 项目部署：完整项目直接放置在webapps目录下，支持自动解压部署压缩包。
  4. 代理联动：可通过Nginx配置反向代理，将对应请求转发至Tomcat服务，实现动静分离架构。

三、MySQL（MariaDB）数据库全操作

（一）基础环境配置

  1. 安装命令：通过dnf命令安装服务器端与客户端软件包： 
    # 安装MariaDB服务器端与客户端
dnf -y install mariadb-server mariadb
# 仅安装MySQL客户端（远程连接时缺少命令用）
dnf -y install mysql·
  2. 服务管理： 
    # 启动MariaDB服务
systemctl start mariadb
# 可选：设置开机自启
systemctl enable mariadb
  3. 基础信息：默认端口3306，数据存储在专用目录，需通过SQL语句查看；默认存储引擎为InnoDB（MySQL 5.5及以后版本），早期版本为MyISAM，查看存储引擎命令： 
    SHOW ENGINES;

（二）数据库基础操作

  1. 连接命令： 
    # 完整连接格式（远程/指定端口）
mysql -h 服务器IP -P 端口号 -u 用户名 -p
# 本地连接（root用户、无密码、默认3306端口，可简化）
mysql
# 示例：远程连接创建的用户“李四”
mysql -h 192.168.66.195 -u 李四 -p123
  2. 核心SQL操作： 
    # 查看所有数据库
SHOW DATABASES;
# 创建数据库（如wordpress、MatePrice，库名支持字母、数字、下划线，纯数字不可用，区分大小写）
CREATE DATABASE wordpress;
CREATE DATABASE MatePrice;
# 删除数据库（谨慎操作）
DROP DATABASE 库名;
# 切换数据库（后续操作针对该库）
USE wordpress;
  3. 注意事项：不推荐直接修改数据库名，建议新建库后迁移表数据；新创建的数据库默认为空，需后续创建数据表才能存储业务数据。

（三）用户创建与权限管理

  1. 用户类型区分：默认root用户为本地用户，仅能本机登录；项目远程连接需手动创建远程用户。
  2. 创建远程用户： 
    # 创建允许任意IP登录的用户“李四”，密码“123”
CREATE USER '李四'@'%' IDENTIFIED BY '123';
# 可选：创建仅指定IP登录的用户
CREATE USER '用户名'@'192.168.66.%' IDENTIFIED BY '密码';
  3. 权限授予：新用户默认无数据库操作权限，需手动授权： 
    # 授予用户所有数据库、所有数据表的全部权限
GRANT ALL PRIVILEGES ON *.* TO '李四'@'%';
# 可选：授予指定数据库（如wordpress）的全部权限
GRANT ALL PRIVILEGES ON wordpress.* TO '李四'@'%';
  4. 生效方式：授权后需重新登录MySQL客户端，权限才能生效。

四、项目部署与多服务关联

（一）涉及项目与环境准备

  1. 核心项目：WordPress（WordPrice，PHP博客项目）、MatePrice（MapPrice/modern price，PHP项目）、my pros等，需整合Nginx、Apache、PHP、MySQL多服务协同运行。
  2. 环境验证：先通过MySQL连接命令验证远程数据库连接是否正常，确保数据库服务可访问。

（二）语言与数据库连接依赖

  1. 中间工具要求：不同编程语言连接MySQL需安装对应中间件/扩展：
    • PHP：需安装mysqli或PDO扩展，实现代码与数据库的交互（写入数据、创建数据表等）；
    • Java：需使用JDBC连接器（对应jar包）；
    • Python：需安装专属MySQL连接工具包。

（三）部署中的权限问题与解决

  1. 数据库配置填写：项目连接数据库时，需在配置文件中填写数据库名（如wordpress）、服务器IP（如192.168.66.195）、用户名（如李四）、密码（如123）及表前缀（如wp_）。
  2. 文件写入权限问题：提交配置时可能出现“无法写入文件”错误，原因是Apache服务需往项目目录写入数据库配置文件（如.php文件），解决方式：
    • 修改项目目录所有者为Apache进程所有者；
    • 通过setfacl命令调整目录权限，赋予Apache用户读写权限。

（四）项目使用与管理

  1. 管理员配置：部署完成后，需创建项目管理员用户（如用户名2509，密码123）。
  2. 前后台功能区分：
    • 后台：用于管理网站内容，支持修改网站外观、发表文章等操作；
    • 前台：用于展示已发布内容，支持用户评论、回复等交互功能。

五、安全配置与整体架构

（一）HTTPS加密配置

  1. 配置前提：现有访问多基于HTTP协议，需升级为HTTPS，基于端口的虚拟主机访问逻辑保持不变。
  2. 核心步骤：
    • 添加HTTPS配置模板至Nginx的service相关配置中；
    • 生成并配置SSL证书，调整证书层级，将对应证书文件复制到指定目录；
    • 启动服务后，通过https://www2.xxx.com等地址测试访问，确保静态页面正常加载，且MatePrice、WordPress等多项目访问结果一致。
  3. HTTP自动跳转HTTPS：在Nginx配置中添加跳转规则，确保无论访问HTTP还是HTTPS地址，最终都指向加密的HTTPS页面，且URL保持不变，保障访问安全性。

（二）完整Web架构

最终构建“Nginx（反向代理）→ Apache/Tomcat（动态资源处理）→ MySQL（数据存储）→ 多项目部署”的完整架构，同时支持HTTPS加密，实现动静分离与安全访问。

（三）学习规划

  1. 基础阶段：掌握Nginx、Apache、Tomcat的配置与项目部署，熟练使用相关bash操作命令。
  2. 数据库阶段：先深入学习MySQL（MariaDB），包括数据表增删改查、数据记录操作、用户权限精细化管理，实现项目与数据库的完整对接；后续拓展学习Redis等非关系型数据库。
  3. 进阶阶段：深化SQL语句、数据库与Web项目的联动，优化架构性能，实现更复杂的企业级应用搭建。

六、问题排查与环境优化

（一）常见部署问题排查

  1. 数据库连接失败：若minepress等项目提示“数据库设置不正确”，通过查看MySQL日志定位问题，常见原因包括缺少依赖包（如Java连接MySQL的jar包）、配置参数错误（IP、用户名、密码有误）。
  2. 配置与依赖问题：通过查看Apache、Nginx日志，排查配置错误、依赖缺失等问题；PHP报错可直接通过页面显示的报错信息定位问题。

（二）环境一致性保障

  1. 版本兼容：搭建LAMP（Linux+Apache+MySQL+PHP）环境时，确保各服务版本兼容，依赖包完整（如PHP的mysql扩展、Apache的进程权限配置）。
  2. 权限统一：不同项目（如WordPress与自定义项目）解压后，需统一调整目录权限，避免因所有者不一致导致的访问或写入错误。
