Linux 软件安装与系统核心操作

介绍《Linux 软件安装与系统核心操作》，涵盖Linux系统核心操作视频内容整合总结、软件安装相关和两种核心流程等实践要点。

Linux系统核心操作视频内容整合总结

视频围绕Linux系统的软件安装（源码包+DNF仓库配置）与用户管理两大核心模块展开，结合多版本系统（CentOS 7/9、Rocky Linux）实操演示，详细讲解关键流程、配置方法及注意事项，同时补充局域网DNF源配置细节，具体内容如下：

一、软件安装相关

（一）源码包安装

1. 两种核心流程

  • 常见流程：获取源码包→解压进入目录→执行configure（需解决报错）→make→make install。

  • 特殊流程（无configure文件但有makefile文件）：解压源码包（如trip相关包，压缩格式tjz为tar.gz缩写，可通过file命令验证、tar命令解压）→切换至解压目录→安装make（dnf search make查找包，dnf install make安装）→安装GCC（C语言编译工具，解决make报错）→执行make（警告非错误，不影响执行）→执行make install（复制命令及帮助文档到系统默认目录，如/usr/bin，实现任意位置调用）。

2. 优势与劣势

类别 具体内容
优势 1. 开放源码，可自行修改功能；2. 安装时可选择所需功能模块；3. 安装文件集中在指定目录，卸载时删除目录即可；4. 适配服务器资源，运行更稳定高效
劣势 1. 安装过程复杂，需手动解决编译依赖；2. 需安装编译工具（如GCC）；3. 编译耗时较长，对比rpm包无需编译的特性更繁琐

3. 实操示例（以Nginx为例）

（1）准备工作

  • 避免端口冲突：Nginx与Apache默认均占用80端口，同一台虚拟机不可同时运行，需关闭其中一个服务。

  • 解压源码包：将下载的Nginx压缩包（如.tar.gz格式）解压至目标目录，进入解压后的目录。

（2）关键文件查看

  • README文件：包含软件功能、官网地址（如nginx.org）、依赖说明等基础信息。

  • configure文件：绿色可执行文件，用于指定安装路径（如./configure --prefix=/usr/local/nginx）、开启功能模块，同时检测系统是否具备编译条件（如编译工具、依赖库）。

（3）解决编译依赖

  • 安装GCC：执行dnf install gcc，解决C语言编译工具缺失问题。

  • 安装依赖库：依次安装pcre-devel（PCRE扩展库）、zlib-devel（zlib扩展库），解决configure检测时的依赖报错。

（4）编译与安装

  • 编译：执行make命令，根据configure生成的Makefile文件将源码转换为二进制文件。

  • 安装：执行make install命令（或合并为make && make install，确保编译成功后才执行安装），安装文件会生成在--prefix指定的路径（如/usr/local/nginx）。

（5）启动与测试

  • 启动服务：执行/usr/local/nginx/sbin/nginx，通过ss -antp查看80端口是否被Nginx监听。

  • 验证：关闭防火墙后，在浏览器输入服务器IP，可看到Nginx默认页面，确认安装成功。

4. 适用场景与现状

  • 适用场景：网络源、本地DNF源无所需软件，或rpm包安装失败时使用；旧系统中需安装特定版本服务（光盘镜像版本较旧）时常用。

  • 现状：新系统中rpm包安装占比更高，但源码包安装仍是重点考点。

5. 卸载与服务管理

  • 卸载：先停止对应服务（如/user/local/NDXSB/NDX stop），再删除安装目录（如/user/local/links），避免服务运行时删除出问题。

  • 服务管理差异：rpm包安装的服务可通过systemctl命令管理（启动、停止、重启、查看状态），源码包安装的服务暂不支持，后续将讲解解决方案。

（二）DNF仓库配置（本地+网络+扩展+局域网）

1. 本地DNF仓库

  • 核心步骤：剪切/etc/yum.repos.d/下所有默认.repo文件到其他位置（使其失效）→创建自定义配置文件（含仓库名称、gpgcheck=0（关闭GPG校验）、baseurl（指定挂载点路径））→确保挂载点目录（如/mnt）存在Packages（存储rpm包）和repodata（存储依赖关系）两个核心目录→执行挂载操作→运行dnf clean all即可安装；除dnf clean all外，其余步骤无严格顺序要求。

  • 缺点：每台服务器需挂载约10GB的ISO镜像，常用rpm包仅数百MB，浪费存储资源；无物理光驱的服务器需先传输ISO文件再挂载，操作繁琐。

2. 网络DNF仓库

（1）默认官方源

虚拟机恢复初始快照后，默认使用官方网络源，无需额外配置即可通过DNF安装软件。

（2）国内网络源配置

  • 常见国内源：阿里源、清华源、163源、华为源，部分源不支持特定系统版本（如阿里源不提供CentOS 7版本，推荐华为源）。

  • 配置流程：备份/etc/yum.repos.d/下原有.repo文件→创建新配置文件（如test.repo）→为AppStream和BaseOS仓库分别配置国内源baseurl（通过对应开源镜像站获取地址）→添加gpgcheck=0；部分源提供sed命令可快速修改配置。

  • 版本补充：CentOS 9无默认wget工具，需自行安装（安装包名称与命令名称一致）。

3. 扩展网络源（EPEL）

  • 引入原因：默认AppStream和BaseOS仓库的rpm包有限，无法满足特殊软件安装需求（如ntfs-3g，用于NTFS文件系统挂载）。

  • 安装与使用：执行dnf -y install epel-release，自动生成epel.repo配置文件→安装后可通过dnf -y install ntfs-3g成功获取扩展包，该包显示来自EPEL仓库。

4. DNF安装包保存设置

  • 默认机制：安装完成后自动删除rpm包，多台服务器安装同一软件需重复下载，浪费资源。

  • 修改配置：编辑/etc/dnf/dnf.conf文件，添加keepcache=1（1表示保存，0表示删除）和cachedir=/指定路径（如/var/cache/dnf）→修改后即时生效，安装包按仓库分类存储在指定路径，便于跨服务器复用。

5. 局域网DNF源配置（以9版本为例）

（1）核心原理与前提

  • 局域网DNF源优势：无需像网络源重复下载，也无需像本地源存储完整光盘文件，仅需存储一次即可供多客户端使用。

  • 硬件要求：至少需两台虚拟机，分别作为服务器端和客户端，不可单台虚拟机同时兼任。

（2）服务器端配置步骤

  • 安装HTTP服务（阿帕奇）：目的是通过HTTP协议向客户端传输rpm包及依赖关系，服务对应安装包名为httpd，安装后系统会生成默认目录/var/www/html（未安装时该目录不存在）；安装方式可通过本地源（如挂载光盘）或网络源安装，无强制限制。

  • 存放rpm包及依赖：将系统中/media目录下的rpm包及依赖关系复制到/var/www/html目录，可通过du -sh命令查看目录占用空间。

  • 启动服务与环境配置：启动HTTP服务执行systemctl start httpd.service（.service可省略），通过ss -ant查看是否监听80端口；关闭防火墙执行systemctl stop firewalld，避免阻碍客户端连接；通过ip addr查看服务器端IP（如示例中的192.168.5.141）。

  • 测试服务：在服务器端浏览器输入自身IP，可看到HTTP测试界面，且能访问/var/www/html下的rpm包及依赖文件（如AppStream、BaseOS目录）。

（3）客户端配置步骤

  • 基础检查：确保客户端与服务器端在同一网段，通过ping服务器IP验证连通性；检查本地光盘（SR0）未挂载，避免优先使用本地源。

  • 修改DNF配置文件：路径为进入/etc/yum.repos.d/目录，将原有.repo文件移至备份目录（如新建的bak目录），新建自定义.repo文件；内容需配置仓库名称、基础URL（指向服务器端/var/www/html下的包存放路径，如http://192.168.5.141/AppStream）、gpgcheck=0（关闭GPG校验）、enabled=1（启用该仓库）。

  • 测试安装：执行dnf install命令安装软件（如tree、vim），验证是否通过服务器端DNF源获取包及依赖。

6. 7版本DNF源配置差异

（1）国内源配置简化

部分7版本（如Super S7 7.6）可通过wget命令直接下载国内源（如阿里源、清华源）的配置文件，默认保存至/etc/yum.repos.d/，覆盖原有文件后无需手动修改，直接生效。

（2）本地源配置差异

  • 配置文件模板：系统自带media.repo模板文件，可直接复制修改，支持多光盘（如SR0、SR1、SR2）路径配置，无需使用时可注释或删除对应行。

  • 光盘挂载与路径：7版本光盘挂载后（如挂载至/mnt），rpm包及依赖直接存放在挂载根目录，无需进入AppStream、BaseOS子目录，配置文件中baseurl直接写挂载路径即可。

  • 命令兼容性：7版本默认使用yum命令（dnf需手动安装或通过dnf-3兼容），配置逻辑与9版本一致，仅文件路径和命令名称有细微差异。

二、用户管理相关

（一）核心关联与操作特性

  • 关联关系：与软件安装（观察服务安装后是否生成服务用户）、权限设置（用户增多需管控权限）紧密相关，需先学用户管理再学权限管理。

  • 操作特性：用户创建、软件安装等操作均为永久性，相关信息记录在配置文件中，关机重启后仍有效。

（二）用户身份识别

  • 识别方式：使用者通过用户名区分登录账号，操作系统通过UID（用户ID）辨别身份，UID相同则视为同一用户。

  • 合法要求：使用系统资源（内存、CPU、硬盘空间等）需拥有合法账号，部分服务用户无需登录系统。

（三）关键配置文件/etc/passwd

该文件以冒号为分隔符，每行分为7列，各列含义如下：

列数 内容 详细说明
1 用户名 与lastlog等文件用户信息对应，用于标识用户
2 密码占位符 旧版存加密密码，现因安全（权限644，所有用户可查看），密码加密后存于/etc/shadow，此处用x占位；有x需验证密码登录，无x输对用户名即可登录（仅本地可见，工作中禁止取消x）
3 UID（用户ID） 1. 范围：常见0-65535，现支持2^32次方（约42亿9000万）；2. 分类：0为root，1-999为系统/服务用户，1000-65535为普通用户（7版本前普通用户UID从500开始）；3. 例外：65534为特殊UID，了解即可
4 GID（组ID） 记录初始组ID（创建时默认加入，唯一）；用户可加多个附加组（获取权限），附加组信息不显示
5 解释说明信息 最初记录部门、联系方式等，现多为空或填用户名；图形化本地登录优先显示该列，纯字符界面无限制
6 家目录 登录后默认所在目录（root为/root，普通用户为/home/用户名）
7 shell类型 1. 常见：/bin/bash（默认，支持正常登录）、/sbin/nologin（服务用户禁用登录）；2. 其他：如/bin/sh、/sbin/sync等，部分仅支持特定命令

（四）组相关概念

  • 初始组：用户创建时默认加入的组，唯一，/etc/passwd第4列记录其GID。

  • 附加组：用户为获取权限额外加入的组，不在/etc/passwd中显示。

  • 当前组：默认是初始组，可通过命令切换为任意附加组；用户新建文件的所属组由当前组决定。

（五）相关配置文件与系统限制

  • UID范围限制：系统通过/etc/login.defs文件限制普通用户UID范围（默认1000-60000），超出可修改该文件调整。

  • 组信息文件：/etc/group记录GID与组名的对应关系，后续单独讲解。

（六）实操注意事项

  • 配置生效：修改/etc/passwd等文件后，用户需重新登录，配置才生效（系统仅登录时读取配置）。

  • 避坑点：禁止创建UID相同的用户，避免系统误判身份；取消密码占位符x等操作为反面案例，工作中禁止操作。

三、补充知识点

  • 命令执行结果判断：通过echo $?查看上一条命令执行结果，返回0表示成功，非0表示失败（绝大多数场景适用，存在极少数人为定义异常的情况）。

  • 路径切换必要性：源码包安装时建议进入解压目录执行命令，便于生成和查找Makefile等临时文件，避免因路径问题导致命令执行失败。

  • 视频包含大量实操演示（修改配置文件、安装依赖工具、验证安装效果等），部分操作需区分系统版本。

  • 学习建议：课后需复习命令与配置流程（如mount -o loop 镜像路径 挂载点），结合视频回顾实操细节；主动记忆基础内容，面试重点考察操作系统、服务集群、虚拟化等相关知识。

  • 时间调整：课程当前12点下课，后续上课时间可能延迟（如11点后开始），以避开就餐高峰。

  • 后续预告：将深入讲解/etc/login.defs、/etc/group等配置文件，以及源码包服务管理问题的解决方法、局域网DNF源具体配置步骤。
