Linux 移动介质挂载、Vim 与压缩打包

介绍《Linux 移动介质挂载、Vim 与压缩打包》，涵盖Linux挂载相关操作与知识、挂载信息查看与特殊选项和移动硬盘/U盘挂载等实践要点。

Linux视频主要内容总结（修正版）

一、Linux挂载相关操作与知识

（一）挂载信息查看与特殊选项

  1. 讲解了挂载信息的查看操作，提及远程连接命令与默认设置，说明这类默认设置通常不变，求职时一般不会被问及，深入了解可查看mount帮助信息（man mount）或相关书籍。（注：原文“美甲”为笔误，推测为“默认”；“mod”应为mount）

  2. 介绍七个特殊选项含义，包含rw（读写）、suid（用户级SetUID权限）、sgid（组级SetGID权限）、dev（允许访问挂载设备的特殊文件）、exec（允许执行挂载目录下的可执行文件）、是否自动挂载stable内容（稳定挂载选项）、是否允许普通用户挂载、async（异步写入，数据先存内存再同步到磁盘，默认设置），还提到部分选项是此前课程见过的缩写或例外情况，相关练习已完成，本次不再重复。（注：修正术语错误：“suyd”→suid，“dv”→dev，“psec”→exec，“s table”→stable，“asc”→async）

（二）移动硬盘/U盘挂载

  1. 接口与虚拟机设置：USB接口分2.0、3.0、3.1、3.2等类型，虚拟机默认可能不识别3.0及以上接口设备，需在虚拟机右键设置中将“USB控制器”改为3.1（建议先关机再修改），否则物理机能识别但虚拟机无法识别。

  2. 设备连接选择：U盘插入物理机后，VM（虚拟机软件如VMware）会检测到新USB设备，提供“连接到主机（Windows）”或“连接到虚拟机”选项，重启虚拟机后仍可通过虚拟机右下角USB设备图标重新选择连接目标。

  3. 文件系统识别与挂载结果可在Windows中通过属性查看U盘文件系统类型（如exFAT、fat32、fat16、ntfs等），Linux对不同文件系统识别情况不同，不识别时虽能在设备监控（如lsblk）中发现U盘，但无法挂载。（注：“espad”为笔误，修正为exFAT）

  4. 以exFAT文件系统U盘为例，连接虚拟机后，可通过fdisk -l、lsblk、lsblk -f等命令查询设备信息，fdisk -l能查看磁盘标签类型与分区情况，lsblk -f可明确文件系统类型。

  5. 挂载需选正确分区（如/dev/sdb1，注：sda1通常为系统分区，外接设备多为sdb及以后编号），执行挂载命令（如mount /dev/sdb1 /mnt/usb）后可通过挂载点（/mnt/usb）访问、读写数据，比如将history命令输出结果重定向保存到U盘（history > /mnt/usb/history.log）。

  6. 卸载与断开连接：使用umount命令卸载，可指定挂载点（umount /mnt/usb）或设备文件名称（umount /dev/sdb1），卸载后才能断开U盘与虚拟机的连接（点击虚拟机右下角USB设备图标选择“断开连接”），在物理机查看U盘数据。

  7. 不同文件系统的处理exFAT文件系统：在Linux 7.6等版本中默认不识别，需安装exfat-utils和fuse-exfat包（EPEL源提供，命令：yum install -y exfat-utils fuse-exfat），依赖相对较少，Linux 9版本默认支持，建议在9版本中操作。（注：“espat”为笔误，修正为exFAT）

  8. ntfs文件系统：Linux默认不识别，需安装ntfs-3g包（可通过EPEL源安装：yum install -y ntfs-3g，无需手动下载传输），安装后可正常挂载读写。

  9. fat32/fat16文件系统：在新版本Linux中通常可直接挂载，无需额外操作。

（三）光盘与ISO文件挂载

  1. 光盘挂载：虚拟机中的光盘设备（/dev/sr0）实际映射Windows中的ISO镜像文件，将ISO文件加载到虚拟机的“虚拟光驱”后，虚拟机开机即可识别为真实光盘。

  2. ISO文件挂载ISO文件在Windows中是镜像文件，传到Linux后为普通文件，Linux不通过文件后缀区分文件类型，需通过file命令（file xxx.iso）识别。

  3. ISO文件虽非块设备，但可使用mount -o loop xxx.iso /mnt/iso命令挂载（-o loop模拟块设备），挂载后能查看其中与光盘一致的内容（如系统安装文件）。

  4. 卸载同样使用umount命令，指定挂载点（umount /mnt/iso）或ISO文件路径（umount xxx.iso）即可。

（四）挂载注意事项

  1. 同一文件系统无需重复挂载到多个位置，仅需一个读写入口即可实现所有操作。

  2. 同一挂载点不能挂载多个块设备，否则后挂载的设备会覆盖前一个设备的内容（仅显示后挂载设备的数据）。

  3. 挂载点必须是空目录，非空目录挂载后原文件会被临时覆盖（文件未删除，仅隐藏），卸载后恢复可见，建议自行创建空目录（如mkdir /mnt/usb）作为挂载点。

二、VIM编辑器相关教学

（一）VIM与VI的核心差异

  1. 功能与显示：VIM（VI Improved）功能更丰富，支持语法高亮（打开文件有字体颜色区分）、代码补全、语法错误提示等；VI功能简化，无语法高亮功能，若系统中vi是vim的软链接（ls -l /usr/bin/vi可查看），则打开文件会继承VIM的语法高亮效果。

  2. 安装与使用场景：最小化系统默认未安装VI/VIM，安装VIM可通过命令（yum install -y vim），依赖较少；基础文本编辑可使用VI，复杂操作（如代码编写）建议用VIM。

  3. 字体调整：图形化本地登录时可通过Ctrl + 加号/减号调整终端字体大小，远程连接（如Xshell、SecureCRT）时需在终端软件的“外观设置”中调整字体。

（二）VIM的工作模式及切换

VIM有命令模式、插入模式、末行模式三种核心模式，默认打开文件进入命令模式：

  1. 命令模式：可移动光标、执行复制粘贴/删除/撤销等操作，输入字符仅作为操作指令，不写入文件。

  2. 插入模式：在命令模式下按i（光标前插入）/I（行首插入）/a（光标后插入）/A（行尾插入）/o（下一行插入）/O（上一行插入）可进入，输入内容直接写入文件，按ESC键返回命令模式。

  3. 末行模式：在命令模式下按:（Shift + 分号）进入，可执行保存、退出、替换等操作（如:wq保存退出），完成后自动退出VIM或返回命令模式。

（三）VIM基础操作

  1. 光标移动：基础移动用上下左右键或H（左）/J（下）/K（上）/L（右）；翻页用PGUP（上一页）/PGDN（下一页）；行内跳转用^（Shift + 6，行首）/$（Shift + 4，行尾）；行间跳转用“数字 + G”（如5G跳转到第5行）、G（末行）、gg（首行）。

  2. 文件内容修改：删除（dd删除当前行，3dd删除3行，x删除光标所在字符）；复制粘贴（yy复制当前行，3yy复制3行，p粘贴到光标后，P粘贴到光标前）；替换（r替换单个字符，R进入替换模式）；撤销（u撤销上一步操作，Ctrl + r反撤销）。

  3. 保存与退出进阶：末行模式输入:w单独保存，:w /path/newfile另存为，:q退出（未修改时），:q!强制退出（丢弃修改），:wq保存退出；命令模式按ZZ（Shift + zz）可快捷保存退出。

（四）VIM文件操作原理

  1. VIM打开文件时会将硬盘文件复制到内存（创建缓冲区），用户修改的是内存中的副本，执行:w命令后，修改内容才会同步写入硬盘原文件。

  2. VIM运行时为交互式进程（可通过ps aux | grep vim查看），仅完成保存退出（:wq）或强制退出（:q!）后，进程才终止。

（五）VIM进阶替换功能

在末行模式下通过:s（substitute）命令实现替换，格式与效果如下：

  • 基础替换：:s/旧内容/新内容（替换当前行第一个匹配项）

  • 行内全替换：:s/旧内容/新内容/g（g即global，当前行所有匹配项）

  • 指定行范围替换：:3,5s/旧内容/新内容/g（替换第3-5行所有匹配项）

  • 全文件替换：:%s/旧内容/新内容/g（%代表整个文件）

  • 询问式替换：:%s/旧内容/新内容/gc（c即confirm，每处匹配均询问是否替换）

三、打包与压缩相关知识

（一）基础概念

  1. 打包：将多个分散的文件/目录合并为一个打包文件（如.tar），方便传输与管理，解包后还原为原始文件结构，文件总体大小无明显变化。

  2. 压缩：通过压缩算法（如gzip、bzip2）优化二进制数据存储，减少文件体积，重复数据越多压缩效果越明显，不同压缩算法的压缩率与速度不同。

（二）Linux系统中的打包压缩命令（tar命令为主）

  1. tar命令核心用法基础选项：-c（创建打包文件）、-x（解包/解压缩）、-v（显示操作过程）、-f（指定目标文件，必须放在选项最后）、-t（查看压缩包内文件列表）。常见组合：tar -cvf file.tar /path（打包）、tar -xvf file.tar（解包）、tar -tvf file.tar（查看内容）。

  2. 排除文件：使用–exclude选项跳过指定文件，格式为tar -cvf file.tar –exclude=file1 –exclude=dir2 /path，一个–exclude对应一个排除对象。

  3. tar结合不同压缩方式：支持三种主流压缩方式，命令格式与后缀对应如下： gzip压缩：tar -zcvf file.tar.gz /path（压缩）、tar -zxvf file.tar.gz（解压缩），后缀为.tar.gz或.tgz，压缩速度快，压缩率中等。

  4. bzip2压缩：需先安装bzip2工具（yum install -y bzip2），命令：tar -jcvf file.tar.bz2 /path（压缩）、tar -jxvf file.tar.bz2（解压缩），后缀为.tar.bz2，压缩率高于gzip，速度稍慢。

  5. xz压缩：tar -Jcvf file.tar.xz /path（压缩）、tar -Jxvf file.tar.xz（解压缩），后缀为.tar.xz，压缩率最高，耗时相对较长。

（三）其他压缩工具（ZIP）

  1. 安装：需先安装unzip再安装zip（避免依赖检测失败），命令：yum install -y unzip zip。

  2. 操作命令：压缩文件zip file.zip file1 file2；压缩目录需加-r（递归）选项：zip -r dir.zip /path/dir；解压缩：unzip file.zip，指定解压路径用-d：unzip file.zip -d /mnt。

  3. 与tar对比：zip压缩软链接时会将链接指向的原文件一并压缩（tar默认仅打包链接本身）；相同目录压缩后，zip文件体积通常大于tar结合xz/gzip的压缩包。

特性 zip 压缩工具 tar + 压缩算法（xz/gzip/bzip2）
默认处理逻辑 不打包软链接本身，而是跟随软链接，将其指向的原文件/目录完整压缩（相当于“解引用”后打包）。
例：若 link.txt -> /home/user/file.txt，zip 会压缩 /home/user/file.txt 而非 link.txt 链接文件。		 仅打包软链接本身（保留链接属性：目标路径、权限、创建时间等），不跟随指向原文件，原文件不会被包含。
例：打包后仅保留 link.txt 作为链接文件（大小仅几字节），解压后仍为指向原路径的软链接（需原文件存在才有效）。
是否可调整行为 支持通过参数修改：
zip -y 压缩包.zip 软链接 → 强制打包软链接本身（不跟随原文件），与 tar 默认行为一致。		 支持通过参数跟随链接：
tar -h -zcvf 压缩包.tar.gz 软链接 → -h（–dereference）参数表示解引用，打包原文件而非链接（与 zip 默认行为一致）。
适用场景 适合需要“完整备份软链接指向内容”的场景（如迁移文件时需包含依赖数据），但可能导致压缩包包含冗余文件。 适合仅需备份链接关系（无需原文件）或避免重复打包的场景（如原文件已在其他位置备份），压缩包更精简。

（四）辅助命令与工具

  1. du命令：查看目录/文件大小，du -h /etc（-h人性化显示，以KB/MB/GB为单位）显示/etc下各文件/目录大小；du -sh /etc（-s仅显示总大小）直接输出/etc目录递归总大小。

  2. file命令：判断文件类型，可识别无规范后缀的压缩文件，如file file.tar.gz会显示“gzip compressed data”，辅助确定正确的解压缩命令。

四、学习建议与课程预告

  1. 学习建议执行tar命令时“删除开头的根”（如解压时提示“Removing leading `/’ from member names”）并非报错，是tar的安全机制，避免解压缩覆盖系统根目录下的同名文件；-f选项后必须紧跟目标文件，其他选项顺序可任意调整。

  2. 安装工具时若提示依赖缺失（如“requires xxx”），需先通过yum install -y xxx安装依赖包，再安装目标工具；高强度学习中要合理分配休息时间，命令用法需通过实际操作验证（如多练习不同文件系统的挂载、不同压缩方式的打包）。

  3. 修改/etc/passwd、/etc/fstab等系统配置文件时，建议先备份（如cp /etc/passwd /etc/passwd.bak）或修改副本，避免错误操作导致系统运行异常。
