# 视频主要内容总结
## 一、VIM相关操作与模式
1. **VIM工作模式补充**：在命令模式、编辑模式、末号模式基础上，新增“微模式”（可视框模式），通过`Ctrl + v`进入，可纵向选中多行内容，输入大写`i`切换至编辑模式，添加字符后按`ESC`能实现多行批量添加字符（如批量注释）。
2. **VIM使用技巧**：取消文本选中高亮可查找不存在的字符串；需记忆`GG`（跳转到最后一行）、`20G`（跳转到第20行）、`DD`（删除一行）、`YYP`（复制粘贴）等常用命令，提升操作效率。
3. **交换文件（.swp文件）**
    - **产生机制**：执行`VIM`命令打开文件时会默认创建`.swp`备份文件，无修改时，保存/不保存退出或断开连接后文件会自动删除；有修改但未保存意外退出，文件会永久保存。
    - **功能作用**：可恢复未保存的修改数据，也能提示多用户修改冲突，避免文件内容被覆盖。
    - **操作处理**：恢复数据后，可在提示界面输入`d`或执行`rm -rf`命令删除`.swp`文件，避免重复出现提示。
4. **行号设置**：临时开启行号在Vim末行模式输入`:set nu`，永久开启需编辑`/etc/vimrc`文件，在最后一行添加`set nu`并保存。

## 二、网卡配置相关操作
### （一）不同系统版本的网卡配置差异
1. **文件路径差异**：九版本系统网卡配置文件位于`/etc/NetworkManager/`目录；七版本系统配置文件保存路径为`/etc/sysconfig/network-scripts/`，文件名称为`ifcfg-ens33`。
2. **配置内容差异**
    - **IP获取方式**：九版本需手动将默认的自动（DHCP）改为“手动”模式；七版本通过配置项指定，`dhcp`为自动获取，`static`或`no`为静态IP（二者效果一致）。
    - **参数设置**：九版本静态IP配置格式为“IP地址/子网掩码,网关”，DNS可配置多个并以分号分隔；七版本需配置`IPADDR`、`NETMASK`（无需写“/24”）、`GATEWAY`、`DNS`（可写`DNS1`/`DNS2`或直接`DNS`），且配置项等号左侧为大写、右侧为小写。
    - **开机自启**：七版本`ONBOOT=yes`表示网卡开机运行，对应九版本的“自动”选项，两个版本均有“自动、手动、禁用”三个选项，仅存在细微差异。
3. **配置生效方式**：九版本修改配置文件后，需执行`nmcli connection load`载入配置，再执行`nmcli connection up`使配置生效，也可重启系统；七版本未提及特殊的生效命令差异，旧版本通用的`ifdown`和`ifup`命令在九版本中不适用。

### （二）新增网卡配置文件
1. **问题背景**：新添加的网卡（如虚拟机新增网络适配器）无默认配置文件，无法直接设置IP，旧网卡会随系统安装自动生成配置文件。
2. **创建方法**：九版本可通过`nmcli connection add con-name [网卡名] type ethernet ifname [网卡名]`命令直接创建，系统自动生成`UUID`；七版本可复制现有网卡配置文件，修改其中的`UUID`（删除原`UUID`）和网卡名。

### （三）UUID相关说明
`UUID`是硬件的唯一识别编号，硬盘分区名可能因硬件插拔或重启变化，在`/etc/fstab`文件中用`UUID`挂载分区可实现永久挂载；网卡配置文件中的`UUID`用于唯一标识网卡，新增配置文件时系统会自动生成。

### （四）NMCLI命令补充
1. **连接管理**
    - **查看连接信息**：执行`nmcli connection show`（可简写）查看所有网卡连接信息，添加网卡名可查看指定网卡信息。
    - **启动与停止连接**：执行`nmcli connection up/down [网卡名]`启动/停止指定网卡连接。
    - **删除连接**：执行`nmcli connection delete [网卡名]`可删除指定网卡的配置文件，后续可通过`nmcli connection add`重新创建。
2. **设备管理**：执行`nmcli device show`查看硬件设备信息，执行`nmcli device status`查看设备状态，停用设备后需执行`nmcli connection up`重新激活。
3. **reload命令局限**：`nmcli connection reload`仅能重新载入配置文件，无法真正使网卡配置生效，仍需通过`load`和`up`命令或重启系统。

## 三、软件安装相关知识
### （一）安装包类型及差异
| 类型       | 核心特点                                                                 | 安装要求                                                                 |
|------------|--------------------------------------------------------------------------|--------------------------------------------------------------------------|
| 源码包     | 包含完整源代码，可自定义修改功能，需编译为二进制才能安装                 | 需对应编译工具（如C语言需`gcc`），且需解决函数库依赖                     |
| RPM包      | 无源代码，已编译为二进制，可直接安装                                     | 无需编译工具和手动解决函数库，但需处理依赖问题（如A依赖B、B依赖C）       |

### （二）RPM包相关
1. **核心特点**：支持升级、具备强大查询功能、可安全验证、自动指定安装位置，缺点是依赖问题难解决，可能出现“循环依赖”。
2. **命名规则**：格式为“软件名-版本-发布次数-操作系统平台-硬件平台.rpm”，需注意“-”分隔的各部分含义，避免混淆包名。
3. **常用命令**
    - 安装：`rpm -ivh 包全名`（需指定路径）
    - 卸载：`rpm -e 包名`（无需路径）
    - 升级：`rpm -Uvh 包全名`（需新版本，光盘无法升级，需网络源）
    - 查询：`rpm -q 包名`（查是否安装）、`rpm -qa`（查所有已装包）、`rpm -qi 包名`（查包详情）、`rpm -ql 包名`（查包生成文件路径）、`rpm -qpl 包全名`（查未安装包的预期文件路径）、`rpm -qf 文件路径`（查文件所属包）。

### （三）DNF/YUM工具（解决RPM依赖）
1. **工具差异与关联**：旧版本（RHEL 5/6/7）用`yum`，新版本用`dnf`，二者选项和核心功能一致，仅命令名不同，均依赖“仓库”。
2. **核心功能**：可自动解决依赖，只需指定目标包，工具会自动查找并安装所有依赖包。
3. **仓库配置**：仓库来源可为光盘（需指定`/media/AppStream`和`/media/BaseOS`路径）或网络源（系统默认使用官方网络源）。
4. **常用命令**：安装包执行`dnf install 包名`，网速过慢可能导致安装失败，后续会补充讲解DNF安装的更多操作细节。

## 四、实践练习与注意事项
1. **实践任务**：关闭虚拟机后将网卡改为桥接模式，修改为分配的IP地址（修改前用`ping`命令检测IP是否被占用），修改成功后同一教室设备可通过该IP远程连接虚拟机，实操理解`w`（查看登录用户）、`who`（查看当前登录用户）等命令的作用。
2. **注意事项**：远程连接失败可能是防火墙开启，需检查防火墙状态；创建测试用户后，他人可通过该用户登录系统，在`w`命令结果中能看到登录用户及对应IP；上午讲解上述内容，下午将进行周测。
