# 视频内容总结
## 一、误删除数据恢复
### 1. 模拟误删除环境准备
（1）基于已有0N2硬盘（剩余近10GB空间），完成分区操作（需熟练掌握中英文分区显示下的操作方法），通过`fspl`命令保存退出后，使用`mkfs`工具对0N2P2分区进行格式化（原“iPad s”为笔误，应为格式化相关命令）。
（2）格式化完成后，创建挂载点（示例：`mkdir /mnt/3`），将0N2P2分区挂载至该目录，通过`df -h`命令查看分区使用状态：初始占用约100MB，占比2%，挂载目录默认为空。
（3）向挂载目录复制系统常见关键文件（如`/etc/fstab`、`/etc/passwd`、`/etc/shadow`、`/etc/group`等），需明确知晓各文件用途及内容，为后续识别恢复文件提供依据。

### 2. 数据恢复原理
（1）文件删除的核心逻辑：仅断开文件名称与inode的关联，同时在磁盘位图中标记文件占用的块为“可用”，文件实际数据仍保留在磁盘块中，未被立即覆盖。
（2）恢复工具工作机制：通过扫描磁盘块，匹配不同文件类型特有的开头数据标识，定位文件数据起始块后，连续读取后续关联块以还原数据，但无法恢复原文件名称。

### 3. 恢复工具操作
#### （1）工具选择与安装
- 工具名称：`photorec`（全称为`photo recovery`，简写形式），所属安装包为`testdisk`，需通过EPEL扩展源安装。
- 安装步骤：
  1. 确保系统DNF源为默认网络源（本地源无法下载扩展包）；
  2. 安装EPEL源：`dnf install -y epel-release`；
  3. 安装`testdisk`包：`dnf install -y testdisk`（安装后自动包含`photorec`工具）。

#### （2）恢复操作流程
1. 执行`photorec`命令，选择需恢复数据的目标分区（示例：`/dev/sda0N2P2`）；
2. 进入交互界面后，按默认光标位置选择“继续”，根据分区实际文件系统类型选择对应选项（ext系列文件系统选下方选项，NTFS等选上方选项）；
3. 恢复路径默认设为当前目录，恢复文件会存储在自动生成的`RECUP_DIR`目录中；
4. 输入字母`c`启动恢复进程，等待完成后按`q`退出；
5. 恢复文件以`.tst`为后缀，可通过`cat`等命令查看文件内容，识别原文件（示例：`F00008.tst`对应`/etc/fstab`文件）。

### 4. 恢复局限性
（1）无100%恢复保障：即使专业数据恢复公司，也可能仅恢复数据片段，无法还原完整文件；
（2）数据块不连续场景：若文件创建后经多次修改、穿插其他文件操作，会导致数据块分布不连续，恢复时易出现文件片段化，强调日常数据备份的必要性，不可依赖数据恢复作为核心保障。

## 二、磁盘阵列（RAID）
### 1. 基础概念
（1）定义：将多块物理硬盘组合为一个逻辑磁盘，核心价值是提升读写速度或实现数据容错，1978年由加州大学伯克利分校提出。
（2）核心特性：
- 不同RAID级别对应不同存储架构，无级别高低之分，仅适配场景差异；
- 一组RAID在操作系统中仅显示为一块逻辑磁盘，屏蔽底层多块物理硬盘的复杂性。

### 2. 常见RAID级别核心参数

| 参数                   | 具体说明                                                                                                                                                                                                                                                                   |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **RAID 0（条带卷）**      | - 硬盘数量要求：至少2块<br>- 数据存储方式：以固定大小（常见64KB）切分文件，交替存储至多块硬盘<br>- 读写速度：读写速度显著提升（理论随硬盘数量翻倍）<br>- 容错能力：无容错机制，任意一块硬盘损坏则全部数据丢失<br>- 磁盘利用率：100%（需硬盘容量一致，否则超出最小容量的部分无法参与条带化）<br>- 适用场景：对速度要求极高、数据可实时备份的场景（如临时文件处理、高速缓存存储）                                                           |
| **RAID 1（镜像卷）**      | - 硬盘数量要求：至少2块<br>- 数据存储方式：文件完整复制到每块硬盘，无需条带化分割<br>- 读写速度：写入速度无提升（需所有硬盘写入完成才算结束）；读取可分摊并发请求，提升访问承载能力<br>- 容错能力：单盘容错：一块硬盘损坏，可从另一块硬盘读取完整数据（仅硬件容错，误删除会同步生效）<br>- 磁盘利用率：50%（需硬盘容量一致，否则超出最小容量的部分无法参与镜像）<br>- 适用场景：对数据安全性要求极高、并发读取频繁的场景（如服务器系统盘、核心配置文件存储）                       |
| **RAID 10（条带+镜像组合）** | - 硬盘数量要求：至少4块（需为偶数块，先分组组成RAID 1，再将两组RAID 1组合为RAID 0）<br>- 数据存储方式：先对文件进行条带化分割，再将每段数据镜像存储至对应RAID 1组<br>- 读写速度：读写速度高效（条带化优化传输效率）<br>- 容错能力：跨组单盘容错：不同RAID 1组各坏一块硬盘可恢复；同组坏两块则数据丢失<br>- 磁盘利用率：50%（受镜像机制限制，容量取两组RAID 1中最小单盘容量的总和）<br>- 适用场景：对速度和安全性均有高要求的场景（如数据库服务器、核心业务数据存储） |
| **RAID 5（带校验条带卷）**   | - 硬盘数量要求：至少3块<br>- 数据存储方式：文件条带化存储，校验信息（奇偶校验）轮流分布于所有硬盘（避免单一硬盘过度承载校验写入）<br>- 读写速度：读写速度较快（条带化+分布式校验均衡负载）<br>- 容错能力：单盘容错：一块硬盘损坏，通过剩余数据与校验信息推算恢复；坏两块则数据丢失<br>- 磁盘利用率：(n-1)/n（n为硬盘数量，1块硬盘容量用于存储校验信息）<br>- 适用场景：兼顾速度、安全性与磁盘利用率的场景（如企业日常数据存储、办公系统数据盘）                          |
|                      |                                                                                                                                                                                                                                                                        |

### 3. 关键补充概念
#### （1）预备磁盘
- 定义：一块或多块不参与RAID日常运行的备用硬盘，类似“汽车备胎”；
- 作用：当RAID中某块硬盘损坏时，自动替换坏盘并同步数据，缩短故障处理时间，降低硬盘损坏期间的读取压力，减少二次数据丢失风险。

#### （2）硬RAID与软RAID
- 硬RAID：基于独立磁盘阵列卡配置，不依赖操作系统，功能稳定、性能优，是工作中服务器的主流配置方式；
- 软RAID：通过操作系统软件模拟实现，无法完全实现硬件级容错，性能受限，工作中极少使用，无需记忆相关配置命令（如`mdadm`），重点掌握原理即可。

#### （3）配置顺序
- 新服务器部署流程：先配置RAID（如RAID 5、RAID 10），再将RAID逻辑盘作为存储介质，进行操作系统安装和文件系统格式化，底层RAID架构对系统透明。

## 三、学习与实践建议
1. 规范专业术语使用：严格记忆标准术语（如“磁盘容错”“条带化”“镜像卷”等），避免自行命名，确保工作交流无歧义；
2. 优先掌握核心原理：RAID学习重点在于不同级别优缺点、适用场景及数据存储/容错逻辑，硬RAID配置多依赖硬件设备，无需死记软件命令；
3. 区分比喻与专业表述：日常可通过比喻（如“饮水机接水”理解RAID 0速度提升）辅助理解，但面试或工作沟通需使用行业标准术语，体现专业性。
