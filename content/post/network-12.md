## 二、回顾与复习
### （一）MySQL基础回顾
1. **核心参数与配置**
   - 复习MySQL服务参数：`SELECT`语句中星号（`*`）代表查询所有列；数据文件位置及核心配置文件（如`/etc/my.cnf`）。
2. **SQL查询基础（DQL）**
   ```bash
   # 1. 查询所有列
   SELECT * FROM 表名;
   # 2. 指定列查询（过滤列）
   SELECT 列名1, 列名2 FROM 表名;
   # 3. WHERE子句过滤行（按姓名查询）
   SELECT * FROM 表名 WHERE name = '陈海林';
   # 4. 通配符匹配（%代表任意多个字符）
   SELECT * FROM 表名 WHERE name LIKE '陈%';
   # 5. 多条件并列查询（OR）
   SELECT * FROM 表名 WHERE name = '陈海林' OR name = '李国熙';
   # 6. LIMIT子句获取前N行数据
   SELECT * FROM 表名 LIMIT 2; # 获取前2行
   ```
   - 解释：`WHERE`用于行过滤，`%`通配符支持模糊匹配，`LIMIT`可控制结果集行数，提升查询效率。
3. **数据操作语言（DML）**
   ```bash
   # 1. 更新数据（需指定条件，避免全表更新）
   UPDATE 表名 SET 列名 = '新值' WHERE name = '陈海林';
   # 2. 删除数据（删除指定条件数据）
   DELETE FROM 表名 WHERE name = '陈海林';
   # 3. 删除全表数据（表结构保留）
   DELETE FROM 表名;
   # 4. 插入数据（与表列数匹配）
   INSERT INTO 表名 (列名1, 列名2) VALUES ('值1', '值2');
   # 5. 批量插入数据
   INSERT INTO 表名 (列名1, 列名2) VALUES ('值1', '值2'), ('值3', '值4');
   ```
   - 注意：`INSERT INTO`需遵循表结构规则，无默认值且不允许为空的列必须填写值；`DELETE`无`WHERE`条件时会删除全表数据，需谨慎操作。
4. **表结构查看**
   ```bash
   # 查看表结构（列名、数据类型、是否为空、默认值等）
   DESC 表名; # 或 DESCRIBE 表名;
   ```
   - 解释：通过该命令可确认字段是否允许为空（`NULL`）、默认值（`DEFAULT`）等属性；插入数据时，允许为空的字段未填写则值为`NULL`。

### （二）SQL语句分类
- 数据操作语言（DML）：增删改查（`INSERT`/`DELETE`/`UPDATE`/`SELECT`）。
- 数据查询语言（DQL）：核心为`SELECT`查询语句。
- 数据控制语言（DCL）：涉及用户授权、权限管理等。
- 数据定义语言（DDL）：定义数据库、表结构（后续重点学习）。

### （三）数据库与表操作基础
```bash
# 1. 创建数据库
CREATE DATABASE 数据库名;
# 2. 删除数据库（谨慎使用，不可逆）
DROP DATABASE 数据库名;
# 3. 切换数据库
USE 数据库名;
# 4. 跨库操作表（无需切换数据库）
SELECT * FROM DB100.信息; # 操作DB100库下的信息表
```

## 三、核心技术讲解：DDL 表操作体系
### （一）表的基本操作核心命令
- 核心命令框架：创建表（`CREATE TABLE`）、删除表（`DROP TABLE`）、修改表（`ALTER TABLE`），需先牢记命令开头格式，再深入细节用法。

### （二）创建表实践
1. **表的设计思路**
   - 示例场景：收集午餐信息，需包含字段：姓名（`name`）、手机号（`phone`）、地址（`address`）、备注（`remark`）、菜品（`dish`）、菜品数量（`dish_count`）、主食（`staple_food`）、汤品（`soup`）、价格（`price`）、送餐时间（`delivery_time`）。
1. **数据类型选择原则**

| 信息项       | 内容                                                                 |
|--------------|----------------------------------------------------------------------|
| 字段：姓名   | 推荐数据类型：VARCHAR(50)；选择理由：足够存储汉字及较长姓名，灵活度高 |
| 字段：手机号 | 推荐数据类型：VARCHAR(11)；选择理由：作为标识而非计算用途，避免INT类型（可能丢失前导0或超出长度） |
| 字段：地址   | 推荐数据类型：TEXT；选择理由：无需过长存储，LONGTEXT冗余，TEXT足够满足需求 |
| 字段：菜品数量 | 推荐数据类型：INT / SMALLINT；选择理由：数值型，根据实际最大数量选择，SMALLINT更节省空间 |
| 字段：价格   | 推荐数据类型：数值类型（如DECIMAL）；选择理由：需精确存储金额，避免浮点型精度丢失 |
| 字段：送餐时间 | 推荐数据类型：DATETIME / DATE；选择理由：DATETIME含时分秒，DATE仅日期，根据需求选择 |

1. **创建表语句与验证**
   ```bash
   # 1. 创建午餐信息表（基础版，无约束）
   CREATE TABLE lunch (
     name VARCHAR(50),
     phone VARCHAR(11),
     address TEXT,
     remark VARCHAR(255),
     dish VARCHAR(100),
     dish_count INT,
     staple_food VARCHAR(50),
     soup VARCHAR(50),
     price DECIMAL(10,2),
     delivery_time DATETIME
   );
   # 2. 查看表结构（验证创建结果）
   DESC lunch;
   # 3. 插入数据验证表结构合理性
   INSERT INTO lunch (name, phone, dish, dish_count, price) 
   VALUES ('123', '12345678901', '西红柿炒蛋', 1, 15.00);
   ```
   - 注意：换行书写时未加分号可继续输入，加分号后语句执行结束；插入数据需与字段类型匹配。

### （三）字符集与排序方式
1. **字符集核心知识**
   - 作用：决定数据库/表能否存储中文，默认字符集`latin`不支持中文，需指定`UTF8`或`UTF8MB4`。
   - 两种字符集区别：
     - `UTF8`：实际为`UTF8MB3`简称，用3个字节存储一个汉字，支持常用中文。
     - `UTF8MB4`：用4个字节存储一个汉字，支持更多字符（如特殊符号、生僻字），原始环境可能仅显示`MB3`/`MB4`。
2. **中文支持配置方法**
   ```bash
   # 方法1：建库时指定字符集（后续表继承该字符集）
   CREATE DATABASE db2 DEFAULT CHARSET = UTF8;
   # 方法2：建表时指定字符集（单独表支持中文，不依赖库字符集）
   CREATE TABLE 信息1 (
     name VARCHAR(50)
   ) DEFAULT CHARSET = UTF8MB4;
   # 方法3：修改配置文件（永久生效，后续建库建表默认支持中文）
   # 编辑配置文件（如/etc/my.cnf），添加字符集配置（之前课程提及）
   ```
3. **排序方式（COLLATE）**
   ```bash
   # 1. 创建表时指定排序方式（区分大小写）
   CREATE TABLE 表名 (
     列名 VARCHAR(50)
   ) DEFAULT CHARSET = UTF8 COLLATE utf8_bin;
   # 2. 创建表时指定排序方式（不区分大小写）
   CREATE TABLE 表名 (
     列名 VARCHAR(50)
   ) DEFAULT CHARSET = UTF8 COLLATE utf8_general_ci;
   ```
   - 解释：
     - `utf8_general_ci`：不区分大小写（`ci`=case insensitive），查询“李四”会匹配“李四”“LI SI”等。
     - `utf8_bin`：区分大小写（`bin`=binary），仅匹配完全一致的内容。
     - 排序方式直接影响查询结果的匹配规则，需根据业务需求选择。

### （四）表结构修改操作（ALTER TABLE）
1. **修改表名**
   ```bash
   ALTER TABLE lunch RENAME lunch2;
   ```
   - 注意：不推荐频繁修改表名，可能影响关联业务逻辑。
2. **添加列**
   ```bash
   # 1. 默认添加到最后一列
   ALTER TABLE lunch2 ADD 餐具 VARCHAR(20) DEFAULT '筷子' NOT NULL;
   # 2. 添加到第一列
   ALTER TABLE lunch2 ADD 序号 INT FIRST;
   # 3. 添加到指定列之后（如“手机号”之后）
   ALTER TABLE lunch2 ADD 用餐人数 INT AFTER phone;
   ```
   - 数据影响：
     - 表中已有数据时，指定默认值则填充默认值；
     - 未指定默认值且允许为空，字符串类型填充空字符串，数值类型填充0，日期类型填充“0000-00-00”；
     - 不允许为空且无默认值，添加列会报错。
3. **删除列**
   ```bash
   ALTER TABLE lunch2 DROP 用餐人数;
   ```
   - 注意：一次只能删除一列，删除后列及对应数据永久移除，操作不常见，需谨慎。
4. **修改列名与属性**
   ```bash
   # 1. 同时修改列名、数据类型、约束
   ALTER TABLE lunch2 CHANGE 餐具3 餐具 VARCHAR(30) DEFAULT '勺子' NOT NULL;
   # 2. 仅修改列属性（不改变列名）
   ALTER TABLE lunch2 MODIFY 餐具 VARCHAR(50) DEFAULT '筷子' NULL;
   ```
5. **删除表**
   ```bash
   DROP TABLE lunch2;
   ```
   - 注意：删除后表结构和数据均不可逆，删除前需确认表是否无用及数据是否备份。

### （五）约束系统详解
#### 1. 约束的核心作用
- 控制输入数据的有效性，避免无效、重复、不合理数据存入表中（如空值、重复手机号等）。

#### 2. 约束的级别与类型
##### （1）字段约束（作用于单个字段）
```bash
# 1. 创建表时添加字段约束（非空+默认值）
CREATE TABLE lunch3 (
  name VARCHAR(50) NOT NULL, # 非空约束：姓名不能为空
  address VARCHAR(255) DEFAULT '2509', # 默认值约束：未填写时默认“2509”
  dish_count INT DEFAULT 1 # 默认值约束：菜品数量默认1
);
# 2. 已创建表添加字段约束
ALTER TABLE lunch3 MODIFY name VARCHAR(50) NOT NULL; # 添加非空约束
ALTER TABLE lunch3 MODIFY address VARCHAR(255) DEFAULT '2509'; # 添加默认值约束
```
- 核心类型：
  - 非空约束（`NOT NULL`）：字段值不能为空（如姓名、手机号、地址等关键字段）。
  - 默认值约束（`DEFAULT`）：字段未输入值时，自动填充默认值。

##### （2）行间约束（作用于表中多行数据）
- 核心作用：控制字段值在多行间的唯一性，主要包括主键约束和唯一键约束。

### （六）主键约束详解
#### 1. 基本特点
- 核心属性：字段值兼具**唯一**（无重复）和**非空**（无`NULL`）特性，一张表仅能有一个主键。
- 类型限制：`VARCHAR`/`TEXT`类型不建议设为主键（数据比较耗时，可能超时），优先选择`INT`等数值类型。

#### 2. 主键操作方法
```bash
# 1. 为已创建表添加主键（手机号列）
ALTER TABLE lunch2 ADD PRIMARY KEY (phone);
# 2. 删除主键（无需指定列名）
ALTER TABLE lunch2 DROP PRIMARY KEY;
```
- 约束效果：
  - 添加主键前，需清理数据（删除重复值、空值），否则会报错。
  - 添加后，插入/修改数据时，主键字段值重复或为空会报错。

#### 3. 联合主键
- 定义：多列组合作为主键（非多个主键），需多列值共同满足唯一+非空。
- 示例：用户表中“用户名+机器名”作为联合主键，单独一列值可重复，但两列组合不可重复。
- 删除：与单一主键操作一致，`ALTER TABLE 表名 DROP PRIMARY KEY;`。

#### 4. 主键选择原则
- 业务字段优先：选择数据唯一、重要且用于区分数据的业务字段（如学号、身份证号），缺失会导致业务统计不完整。
- 自定义ID备选：创建`INT`类型`ID`列作为主键（与业务无直接关联），比较速度快，提升数据操作效率。

#### 5. 自增主键（AUTO_INCREMENT）
```bash
# 1. 为ID列添加自增属性（需先设为主键）
ALTER TABLE 表名 ADD PRIMARY KEY (ID);
ALTER TABLE 表名 MODIFY COLUMN ID INT AUTO_INCREMENT;
# 2. 取消自增属性（需先取消自增，再删主键）
ALTER TABLE 表名 MODIFY COLUMN ID INT;
ALTER TABLE 表名 DROP PRIMARY KEY;
# 3. 重置自增值（清空表数据+重置自增）
TRUNCATE TABLE 表名;
```
- 核心特性：
  - 系统自动生成主键值，默认起始值1，增量1（插入数据时取当前最大值+1）。
  - 自增属性不能单独存在，需结合主键（或其他键）使用。
  - 注意事项：
    - 删除数据后，自增值不回退（如删除ID=3的记录，下次插入仍为4）。
    - 插入数据时可手动指定自增列值（优先级高于系统生成），后续自动值基于手动最大值递增。
    - `TRUNCATE`与`DELETE`区别：`TRUNCATE`清空数据+重置自增值+保留表结构，`DELETE`仅清空数据。

### （七）唯一键约束详解

### 1. 基本特点
- 核心属性：字段值需唯一，但允许为空（多个空值可共存），一张表可创建多个唯一键，支持多列组合（联合唯一键）。

| 对比维度 | 主键约束       | 唯一键约束          |
| ---- | ---------- | -------------- |
| 核心特性 | 唯一 + 非空    | 仅唯一，允许为空       |
| 数量限制 | 一张表仅能有1个   | 一张表可以存在多个      |
| 查询效果 | 确保返回唯一一条数据 | 若存在空值，可能返回多条数据 |

#### 2. 唯一键操作方法
```bash
# 1. 添加单一列唯一键
ALTER TABLE lunch3 ADD UNIQUE KEY (phone);
# 2. 添加联合唯一键（菜+饭组合唯一）
ALTER TABLE lunch3 ADD UNIQUE KEY (dish, staple_food);
# 3. 修改列允许为空（测试唯一键对空值的处理）
ALTER TABLE lunch3 MODIFY phone VARCHAR(11) NULL;
```
- 联合唯一键特性：多列值组合唯一，单一列值可重复（如“米饭+鸡蛋汤”与“馒头+鸡蛋汤”可共存，“米饭+鸡蛋汤”不可重复插入）。

#### 3. 联合唯一键查看方式
```bash
# 查看表创建语句（含联合唯一键信息）
SHOW CREATE TABLE lunch3;
```
- 解释：通过该命令可明确联合唯一键包含的列及顺序（列顺序影响键定义，先写列排序靠前），也可通过系统表查看键的名称、对应列名。

### （八）键与索引的关系
#### 1. 索引的本质
- 索引类似书籍目录，添加主键或唯一键时，系统会自动创建对应索引。
- 无索引：查询需“全表扫描”（逐行对比数据），效率低。
- 有索引：系统按索引排序数据，查询时快速定位（如按`ID`索引查找，直接定位对应数据位置）。

#### 2. 索引使用建议
- 并非越多越好：过多索引会增加数据插入、修改、删除的开销（需同步维护索引）。
- 不可无索引：关键查询字段无索引会大幅降低效率。
- 合理创建：根据业务需求，在常用查询字段（如主键、唯一键对应的字段）创建索引。
