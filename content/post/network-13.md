## 一、基础核心：SQL语言体系与基础操作
### （一）SQL语言概念与分类
SQL（Structured Query Language，结构化查询语言）按功能分为四大类，覆盖数据操作、定义、控制全流程：
1. **数据查询语言（DQL）**：核心用于数据查询，暂未深入展开具体语句，重点留待后续实操强化。
2. **数据操作语言（DML）**：聚焦数据增删改，核心命令及作用如下：
   ```bash
   INSERT  # 新增数据（如向表中插入一条学生记录）
   DELETE  # 删除数据（如删除分数低于60的记录）
   UPDATE  # 修改数据（如更新学生的联系电话）
   ```
3. **数据定义语言（DDL）**：负责数据库、表的创建、修改、删除与查询，核心命令及作用：
   ```bash
   CREATE  # 新增数据库/表（如创建学生表、课程表）
   USE     # 切换数据库（如USE 学生管理系统，进入目标数据库）
   ALTER   # 修改表结构（如修改字段类型、新增字段）
   SHOW DATABASES  # 查询所有数据库列表
   SHOW TABLES     # 查询当前数据库下所有表列表
   DESC 表名       # 查看表的简单结构（字段名、类型、约束等）
   SHOW CREATE TABLE 表名  # 查看表的完整定义（含索引、约束细节）
   ```
4. **数据控制语言（DCL）**：用于用户管理与权限控制，详见本章节第三部分。

### （二）数据库与表的基础实操
以“成绩信息表”“学生表（student）”“课程表（course）”等为示例，完整演示从数据库到表的创建与设计流程：
1. **表设计核心要素**：
   - 表名：明确业务含义（如“成绩”“student”“course”）；
   - 字段设计：贴合业务需求（如学生表含ID、姓名、生日、性别，课程表含ID、课程名、教师ID，分数表含学生ID、课程ID、分数）；
   - 字段类型：按需选择（姓名用`VARCHAR`、学号/ID用`INT`、分数用`FLOAT`/`DOUBLE`、日期用日期类型）；
   - 长度设置：合理规划（如`VARCHAR(25)`适配姓名，`VARCHAR(50)`适配较长文本）；
   - 基础约束：非空（`NOT NULL`，如姓名不可空）、默认值（`DEFAULT`，如性别默认“未知”）。
2. **基础操作示例**：
   ```bash
   # 创建数据库
   CREATE DATABASE 学生管理系统;
   # 切换至目标数据库
   USE 学生管理系统;
   # 创建学生表（含自增主键、基础约束）
   CREATE TABLE student (
     SID INT PRIMARY KEY AUTO_INCREMENT,  # 学生ID，自增主键
     姓名 VARCHAR(25) NOT NULL,           # 姓名，非空约束
     生日 DATE,                           # 生日，日期类型
     性别 VARCHAR(10) DEFAULT '未知'      # 性别，默认值“未知”
   );
   # 插入数据
   INSERT INTO student (姓名, 生日, 性别) VALUES ('张三', '2000-01-15', '男');
   ```

### （三）DCL：用户管理与权限控制
#### 1. 核心基础
- MySQL服务器默认监听3306端口，客户端通过命令连接：
  ```bash
  mysql -h 服务器IP -P 端口 -u 用户名 -p  # 密码可换行输入，避免暴露在命令历史中
  ```
- Windows客户端工具：Navicat for MySQL（仅支持MySQL）、Navicat Premium（多数据库兼容，需安装激活，可能需关闭防护软件），操作流程：新建连接→填写连接名、协议、服务器IP、端口、用户名、密码→双击连接。
- 用户信息存储：创建的用户数据存储在`mysql`系统库的`user`表中，核心字段：
  - `user`：登录用户名；
  - `host`：登录地址（`localhost`仅本机登录，`%`允许所有客户端登录，可指定具体IP如`192.168.66.192`）；
  - `password`：登录密码。

#### 2. 用户管理核心命令
```bash
# 1. 创建用户（格式：用户名@登录地址，密码必填）
CREATE USER '李四'@'192.168.66.192' IDENTIFIED BY '123';  # 仅192.168.66.192可登录
CREATE USER '王五'@'%' IDENTIFIED BY '456';                # 所有客户端可登录

# 2. 查看用户（需先切换至mysql库，或指定库表）
USE mysql;
SELECT host, user, password FROM user;  # 查看所有用户核心信息
SELECT host, user FROM mysql.user;      # 未切换库时，通过“库名.表名”访问

# 3. 修改用户（主要修改密码，用户名不建议修改，需修改可删除后重建）
ALTER USER '王五'@'%' IDENTIFIED BY '123456';  # 重置王五的密码为123456

# 4. 删除用户（需同时指定user和host，因二者是联合主键）
DROP USER '李四'@'192.168.66.192';
```

#### 3. 权限管理核心命令
```bash
# 1. 查看用户权限
SHOW GRANTS FOR '王五'@'%';  # 查看王五的所有权限

# 2. 授予权限（格式：权限 库名.表名 用户名@登录地址）
GRANT SELECT, INSERT ON 学生管理系统.student TO '王五'@'%';  # 授予学生表的查询、新增权限
GRANT ALL ON 学生管理系统.* TO '王五'@'%';                   # 授予学生管理系统所有表的所有权限
GRANT ALL ON *.* TO '管理员'@'localhost' WITH GRANT OPTION;  # 授予管理员权限（含授权他人的权限）

# 3. 收回权限（格式与授予对应，库表范围需一致）
REVOKE INSERT ON 学生管理系统.student FROM '王五'@'%';  # 收回王五的学生表新增权限
REVOKE ALL ON 学生管理系统.* FROM '王五'@'%';           # 收回王五的学生管理系统所有权限
```
- 关键说明：普通用户即使拥有`*.*`的所有权限，也无授权他人的权限，需通过`WITH GRANT OPTION`额外授予；收回权限时，库表范围需与授予时完全一致（如授予所有表权限后，无法单独收回某一张表的权限）。

## 二、核心机制：表约束、索引与MySQL工作原理
### （一）表约束体系
约束分为字段约束、行间约束、表间约束三类，核心作用是保证数据完整性与唯一性：
1. **字段约束**：非空（`NOT NULL`）、默认值（`DEFAULT`），已在基础实操中讲解。
2. **行间约束**：主键、唯一键，是单表数据完整性的核心：

| 约束类型  | 核心作用            | 关键区别 | 是否可为空 | 核心操作命令                                                                                                                                                                                                               |
| ----- | --------------- | ---- | ----- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 主键约束  | 确保字段非空唯一，提升查询效率 | 表仅1个 | 不可为空  | 建表：`CREATE TABLE 成绩(ID INT PRIMARY KEY AUTO_INCREMENT, 姓名 VARCHAR(25));`<br>添加：`ALTER TABLE 成绩 ADD ID INT FIRST;`→`ADD PRIMARY KEY (ID);`→`MODIFY ID INT AUTO_INCREMENT;`<br>删除：`MODIFY ID INT;`→`DROP PRIMARY KEY;` |
| 唯一键约束 | 确保字段值唯一         | 表可多个 | 允许为空  | 添加：`ALTER TABLE 成绩 ADD UNIQUE KEY (姓名);`/`CREATE UNIQUE INDEX 学号唯一索引 ON 成绩(学号);`<br>删除：`ALTER TABLE 成绩 DROP INDEX 索引名;`                                                                                              |

3. **表间约束**：外键（暂未深入，需多表关联场景后续讲解）。
4. **联合主键**：多列组合作为主键，确保组合值唯一，建表时定义：
   ```bash
   CREATE TABLE 联合表 (
     列1 INT,
     列2 VARCHAR(25),
     PRIMARY KEY (列1, 列2)  # 列1+列2组合唯一
   );
   ```

### （二）索引详解
#### 1. 本质与作用
索引是一种优化查询效率的数据结构，类似书籍目录，可快速定位数据；主键、唯一键会自动生成对应索引，无需手动创建。

#### 2. 分类体系
| 分类维度 | 具体类型 | 核心说明 |
|----------|----------|----------|
| 数据结构 | 树形结构（B+树） | MySQL主流，InnoDB引擎默认使用 |
|          | 哈希结构 | 适用于内存数据库，查询速度快但不支持范围查询 |
|          | 全文索引 | 适用于文本检索（如文章内容关键词查询） |
|          | 空间索引 | 适用于多维数据（如地理位置信息） |
| 字段关联 | 主键索引（聚簇索引） | 表数据与索引存储在一起，按主键排序 |
|          | 唯一索引 | 与唯一键约束关联，确保字段唯一 |
|          | 普通索引 | 无约束，仅用于加速查询 |
|          | 联合索引 | 多列组合创建（如联合主键/唯一键对应的索引） |
| 存储方式 | 聚簇索引 | 即主键索引，数据与索引在同一文件 |
|          | 非聚簇索引（辅助索引） | 索引单独存储，查询需通过索引找主键再获取数据 |

#### 3. 核心操作命令
```bash
# 1. 创建普通索引（按需添加，加速查询）
CREATE INDEX 分数索引 ON 成绩 (分数);  # 给成绩表的分数字段加普通索引

# 2. 查看索引
SHOW INDEX FROM 成绩;  # 查看成绩表的所有索引信息

# 3. 删除索引
DROP INDEX 分数索引 ON 成绩;  # 删除成绩表的分数索引
```

#### 4. 使用原则
- 索引并非越多越好：额外索引会占用存储空间，且增删改数据时需维护索引，降低操作效率；
- 按需添加：频繁作为查询条件的字段（如频繁按“分数”查询）适合加索引；频繁增删改的字段应减少索引。

### （三）MySQL工作原理与查询流程
#### 1. 服务启动与连接
- 默认端口：3306；
- 连接方式：客户端通过`mysql -h 服务器IP -P 端口 -u 用户名 -p`命令连接，建立连接后可执行SQL语句。

#### 2. SQL执行步骤
1. 语法分析：校验SQL语法正确性，确认涉及的表、列是否存在；
2. 优化器处理：生成执行计划，选择最优索引（索引越多，优化器选择成本越高）；
3. 存储引擎执行：按执行计划操作数据，InnoDB引擎默认使用B+树索引结构。

#### 3. 查询效率优化
- 问题现象：客户端反应慢，多因数据库查询效率低；
- 解决方案：合理添加索引（根据查询条件给对应字段加索引，如频繁按“学号”查询则给“学号”加索引）。

### （四）表间关系
1. **核心关系类型**：

## 三、进阶操作：查询体系（联表、多表、复杂查询）
### （一）联表查询（2表关联）
#### 1. 核心基础
- 作用：将多张表的数据结合查询，至少需2张表；
- 关键：找到表间关联字段（如姓名、学号、ID等含义一致的字段），避免无意义的笛卡尔积（如4条数据的表与4条数据的表无关联查询，会产生16条无效结果）；
- 关联字段指定：通过`WHERE`子句或`ON`子句设置。

#### 2. 常见联表类型与示例
```bash
# 1. 内连接（INNER JOIN，默认连接方式，取两表交集）
# 语法：FROM 左表 INNER JOIN 右表 ON 关联条件（INNER可省略）
SELECT 信息表.姓名, 信息表.性别, 排行榜表.分数 
FROM 信息表 JOIN 排行榜表 
ON 信息表.姓名 = 排行榜表.姓名;  # 仅显示姓名匹配的记录

# 2. 左连接（LEFT JOIN，以左表数据为准）
SELECT * 
FROM 信息表 LEFT JOIN 排行榜表 
ON 信息表.姓名 = 排行榜表.姓名;  # 左表所有记录显示，右表不匹配的字段为NULL

# 3. 右连接（RIGHT JOIN，以右表数据为准）
SELECT * 
FROM 信息表 RIGHT JOIN 排行榜表 
ON 信息表.姓名 = 排行榜表.姓名;  # 右表所有记录显示，左表不匹配的字段为NULL
```

#### 3. 字段与条件设置
- 字段指定：若两张表有相同字段名（如“姓名”），需通过“表名.字段名”区分，避免歧义；
- 行条件筛选：联表后可通过`WHERE`子句筛选行，示例：
  ```bash
  # 查询分数大于97的学生信息与分数
  SELECT 信息表.姓名, 排行榜表.分数 
  FROM 信息表 JOIN 排行榜表 
  ON 信息表.姓名 = 排行榜表.姓名 
  WHERE 排行榜表.分数 > 97;
  ```

### （二）多表联合查询（3表及以上）
#### 1. 核心逻辑
以学生表（student）、课程表（course）、分数表（sco）为例，通过表间关联字段（student.SID = sco.学生ID、course.CID = sco.课程ID）逐层关联，支持给表和列起别名简化书写，同时可过滤行和列。

#### 2. 示例代码
```bash
# 给表起别名（s=student，c=course，sc=sco），查询学生姓名、课程名、分数
SELECT s.姓名, c.课程名, sc.分数 
FROM student s
JOIN sco sc ON s.SID = sc.学生ID
JOIN course c ON c.CID = sc.课程ID
WHERE sc.分数 >= 80;  # 筛选分数80及以上的记录
```

### （三）条件查询与聚合函数
#### 1. 条件查询
- 模糊查询：用`like`结合通配符`%`（匹配任意字符）实现，示例：
  ```bash
  # 查询姓名含“理性”的学生信息（原“离异课程”为笔误，修正为“特定姓名”查询逻辑）
  SELECT * FROM student WHERE 姓名 LIKE '%理性%';
  ```

#### 2. 聚合函数
- 特点：输入多个值，输出一个值，用于统计分析；
- 核心函数及示例：
  ```bash
  COUNT(字段名)  # 统计非空值个数（如统计学生总数）
  SELECT COUNT(SID) AS 学生总数 FROM student;
  
  MAX(字段名)    # 求最大值（如查询最高分数）
  SELECT MAX(分数) AS 最高分 FROM sco;
  
  MIN(字段名)    # 求最小值（如查询最低分数）
  SELECT MIN(分数) AS 最低分 FROM sco;
  
  AVG(字段名)    # 求平均值（如查询平均分数）
  SELECT AVG(分数) AS 平均分 FROM sco;
  
  SUM(字段名)    # 求和（如查询所有学生分数总和）
  SELECT SUM(分数) AS 总分合计 FROM sco;
  ```

### （四）子查询（嵌套查询）
#### 1. 核心定义
子查询即SQL语句中嵌套另一个SQL查询，外层查询需先执行内层查询获取结果，相比多条独立SQL语句，效率更高。

#### 2. 应用场景与示例
- 场景1：查询特定条件的关联数据（如查询01课程成绩比02课程成绩高的学生信息）；
- 示例代码：
  ```bash
  # 先通过子查询分别获取学生01、02课程的成绩，再关联比较
  SELECT s.姓名, sc1.分数 AS 01课程成绩, sc2.分数 AS 02课程成绩
  FROM student s
  JOIN sco sc1 ON s.SID = sc1.学生ID AND sc1.课程ID = 1
  JOIN sco sc2 ON s.SID = sc2.学生ID AND sc2.课程ID = 2
  WHERE sc1.分数 > sc2.分数;
  ```
- 场景2：更新数据（用子查询获取需修改的值）：
  ```bash
  # 假设需将“张三”的01课程成绩更新为该课程的平均分
  UPDATE sco
  SET 分数 = (SELECT AVG(分数) FROM sco WHERE 课程ID = 1)
  WHERE 学生ID = (SELECT SID FROM student WHERE 姓名 = '张三') AND 课程ID = 1;
  ```

### （五）分组查询与条件过滤
#### 1. 分组查询（GROUP BY）
- 作用：按特定字段（如学生ID、课程ID）分组，将相同字段值的记录压缩，需结合聚合函数使用；
- 示例代码：
  ```bash
  # 按学生ID分组，统计每个学生的总分、平均分
  SELECT 学生ID, SUM(分数) AS 总分, AVG(分数) AS 平均分
  FROM sco
  GROUP BY 学生ID;
  ```

#### 2. SQL执行顺序与条件过滤
- 执行顺序：`FROM` → `WHERE` → `GROUP BY` → `HAVING` → `SELECT` → `ORDER BY`；
- 条件过滤区别：
  - `WHERE`：在`GROUP BY`前执行，过滤原始数据，无法使用聚合函数；
  - `HAVING`：在`GROUP BY`后执行，过滤分组后的结果，可使用聚合函数；
- 示例代码：
  ```bash
  # 按学生ID分组，筛选总分高于200的学生
  SELECT 学生ID, SUM(分数) AS 总分
  FROM sco
  GROUP BY 学生ID
  HAVING SUM(分数) > 200;
  ```
