# Apache与Nginx服务核心知识整合总结
## 一、Apache（阿帕奇）服务核心内容
### （一）核心实验操作
#### 1. 基于域名的虚拟主机搭建实验
##### （1）实验需求
- 搭建两个基于域名的虚拟主机，分别对应域名示例：`www1.xxx.com`、`www2.xxx.com`，默认网页文件分别为`apache1.html`（内容“3W1”）、`apache2.html`（内容“3W2”），且网页文件存放路径需不同。
- 配置IP访问功能，通过服务器IP（示例：192.168.2.191）访问时能显示指定内容。

##### （2）操作步骤
1. **检查模块与配置文件**：确认`rewrite`模块存在，了解Apache三类配置文件（主配置文件、子配置文件、`.htaccess`文件），优先选择复制模板到`/etc/httpd/conf.d/`目录下编写虚拟主机配置。
2. **配置虚拟主机参数**：两个虚拟主机IP和端口可相同，重点配置不同域名与对应的网页根目录（`DocumentRoot`），无需额外配置无关参数，只需保证根目录路径唯一。
3. **创建目录与网页文件**：按配置路径创建两个网页根目录，分别在对应目录下创建`apache1.html`和`apache2.html`，并写入指定内容。
4. **修改主配置与权限**：调整主配置文件（`httpd.conf`）中默认网页文件优先级，确保`apache1.html`、`apache2.html`能被识别；修改目录权限，可通过新增权限配置标签实现访问授权。
5. **配置域名解析与验证**：在`hosts`文件（路径示例：`/etc/hosts`）中绑定IP与两个域名，通过浏览器访问域名验证是否显示对应网页内容，直接访问IP验证是否正常加载指定页面。

#### 2. Apache缓存设置实验
##### （1）缓存核心原理
缓存功能可加快客户端访问速度，减轻服务器压力，实验中通过设置MIME类型（互联网媒体类型）对应的缓存有效期，控制客户端缓存静态资源的时间。

##### （2）操作步骤
1. **确认模块与MIME类型**：通过以下bash命令检查`expires`模块（缓存过期控制模块）是否加载：
   ```bash
   httpd -M
   ```
   在`/etc/mime.types`文件中查询目标资源（如`.jpg`图片）对应的MIME类型。
2. **配置缓存规则**：在子配置文件（如`/etc/httpd/conf.d/xxx.conf`）中添加缓存配置，针对指定MIME类型设置缓存有效期（示例：图片类型缓存4小时，对应秒数14400），需确保配置放在独立空白区域，避免依赖未加载模块。
3. **重启服务与验证**：通过以下bash命令重启Apache服务：
   ```bash
   systemctl restart httpd
   ```
   - 首次访问图片资源时，状态码为200（表示服务器返回完整资源并缓存）；
   - 缓存有效期内重复访问，状态码显示“200 OK (from disk cache)”（客户端直接使用本地缓存，不向服务器发请求）；
   - 有效期过后访问，状态码为304（服务器确认资源未修改，客户端继续使用缓存）；
   - 若修改资源（如修改图片修改时间），访问状态码恢复为200（服务器返回新资源）。

##### （3）注意事项
- 避免与加密服务（如HTTPS）的缓存功能同时测试，防止相互影响；
- 浏览器默认不缓存超过10MB的资源，实验需选择小于10MB的图片；
- 重复访问测试需新开浏览器窗口，避免当前窗口缓存干扰结果。

### （二）静态与动态资源及前端基础
#### 1. 静态与动态资源区分
| 资源类型 | 核心特征                        | 示例                       | 访问流程                            |
| ---- | --------------------------- | ------------------------ | ------------------------------- |
| 静态资源 | 无逻辑、无数据库交互，内容固定             | 普通文本、图片、视频、HTML/CSS/JS文件 | 客户端访问时，服务器直接返回资源，浏览器解析即可        |
| 动态资源 | 含编程语言逻辑（如PHP）、需数据库交互，内容动态生成 | PHP脚本、带数据库查询的页面          | 客户端访问时，服务器需解析执行后返回结果，需“动态转静态”处理 |

- 日常访问中，动态请求（如淘宝购物车个性化展示）更频繁；
- Apache默认仅处理静态请求，需额外配置以支持动态请求，核心是与PHP的结合。

#### 2. 前端基础补充
- **HTML**：超文本标记语言，用于构建网页结构，通过标签（如`<html>`、`<head>`、`<body>`、`<h1>`、`<p>`）定义页面元素，浏览器预装HTML解释器，可识别标签并渲染页面；
- **CSS**：层叠样式表，用于控制网页样式（如背景色、字体大小），支持样式叠加，可嵌入HTML中通过`<style>`标签使用；
- **JS（JavaScript）**：用于实现网页动态交互（如按钮跳转、页面联动），属于前端静态逻辑代码。

### （三）Apache与PHP结合处理动态请求
#### 1. 核心问题
直接访问`.php`文件时，浏览器会显示源代码而非执行结果，原因是服务器未安装PHP解释器，无法解析动态脚本。

#### 2. 两种结合方式
##### （1）方式一：PHP模块加载（适用于部分系统，如CentOS 7）
1. **操作步骤**：
   - 通过以下bash命令安装PHP解释器：
     ```bash
     yum install php
     ```
     系统会自动生成PHP相关配置文件，并在Apache配置中添加PHP模块（如`php_module`）；
     - 配置文件会通过正则匹配（如匹配`.php`结尾文件），将此类请求交给PHP模块处理，同时添加`index.php`作为默认网页文件。
2. **验证与查看**：通过以下bash命令查看PHP模块是否加载：
   ```bash
   httpd -M | grep php
   ```
   模块文件存于相关依赖目录（如`modules`文件夹）。

##### （2）方式二：FastCGI+PHP-FPM（主流方式，适用于CentOS 9等）
1. **原理与优势**：
   - Apache不直接加载PHP模块，而是将`.php`请求通过FastCGI（通用网关接口）交给`php-fpm`进程处理；
   - `php-fpm`由FastCGI维护，可同时管理多个进程，支持高并发，且是当前PHP默认工作模式（除明确指定模块或使用特定工作模式外）；
   - 对比模块方式：模块方式已逐渐过时，`php-fpm`更灵活，支持按需激活进程，资源消耗更低。
2. **配置与操作**：
   - 安装PHP后，系统自动启动`php-fpm`进程，默认通过套接字（socket）监听请求（非7层网络端口），可在配置文件中设置进程的用户组、PID路径、日志级别等；
   - Apache配置文件通过正则匹配（如匹配`.php`、`.php5`等结尾文件），将请求代理至`php-fpm`进程，处理后返回结果给客户端。

##### （3）简单测试
创建`test.php`文件，写入PHP输出代码（`<?php echo "hello world"; ?>`），通过浏览器访问该文件，验证是否显示“hello world”（而非源代码）。

### （四）Apache版本与HTTPS支持
1. **HTTPS（HTTP/2）版本要求**：Apache需≥2.4.17版本，且OpenSSL需≥1.0.2版本；若版本低于要求（如2.4.6），无法支持HTTP/2。
2. **版本获取与查看**：
   - 可从Apache官网下载对应版本（如2.4.66）；
   - 通过以下bash命令查看Apache版本：
     ```bash
     httpd -V
     ```
   - 通过以下bash命令查看OpenSSL版本：
     ```bash
     openssl version
     ```

### （五）其他补充内容
- 复习Apache配置文件结构，强调主配置、子配置的分工与优先级；
- 通过“领导涨薪”等生活化例子类比技术逻辑，帮助理解缓存、虚拟主机等功能的实际作用；
- 提示实验后可复习地址转发（URL重写）等相关功能，完善Apache服务知识体系。

## 二、Nginx服务核心内容
### （一）Nginx搭建与核心特性
#### 1. Nginx与Apache对比及版本要求
##### （1）核心差异（后续有详细对比表）
Nginx轻量级，配置文件单一（所有功能集中在一个配置文件），资源消耗低；Apache功能丰富但相对笨重。

##### （2）HTTP/2版本要求
Nginx需≥1.9.5版本，OpenSSL要求与Apache一致（≥1.0.2）。

#### 2. Nginx源码包安装步骤
1. **依赖安装**：通过以下bash命令安装基础依赖（用于编译和支持正则、压缩、加密等功能）：
   ```bash
   yum install gcc gcc-c++ pcre zlib openssl-devel
   ```
2. **用户创建**：创建Nginx专属系统用户（无登录权限，指定UID范围），避免权限混乱。
3. **编译与安装**：
   - 解压源码包；
   - 执行`configure`命令并指定参数（如用户组、安装路径、加载统计模块、加密模块、HTTP/2模块等）：
     ```bash
     ./configure --user=nginx --group=nginx --prefix=/usr/local/nginx --with-http_stub_status_module --with-http_ssl_module --with-http_v2_module
     ```
   - 执行以下bash命令编译、安装：
     ```bash
     make && make install
     ```
   - 默认安装路径为`/usr/local/nginx`。

#### 3. Nginx核心配置与操作
##### （1）关键路径
- 配置文件：`/usr/local/nginx/conf/nginx.conf`（源码包）或`/etc/nginx/nginx.conf`（RPM包）；
- 日志文件：错误日志（服务启动错误）和访问日志（客户端访问记录），默认存于`/var/log/nginx`（RPM包）或安装目录下的`logs`文件夹（源码包）；
- 网页根目录：`/usr/local/nginx/html`（源码包），默认包含`index.html`（显示“Welcome to nginx!”）。/usr/share/nginx/html

##### （2）启停与重载命令（bash）
- 启动：
  ```bash
  /usr/local/nginx/sbin/nginx
  ```
- 停止：
  ```bash
  /usr/local/nginx/sbin/nginx -s stop
  ```
- 优雅停止（处理完现有请求后停止）：
  ```bash
  /usr/local/nginx/sbin/nginx -s quit
  ```
- 重新加载配置（热重载，不中断服务）：
  ```bash
  /usr/local/nginx/sbin/nginx -s reload
  ```
- 配置语法检查：
  ```bash
  /usr/local/nginx/sbin/nginx -t
  ```
- 等同于热重载的命令：
  ```bash
  kill -HUP 进程号
  ```

##### （3）端口与访问
默认使用80端口，通过服务器IP可直接访问Nginx默认页面。

#### 4. Nginx高并发特性
##### （1）Master-Worker工作模式
- 通过以下bash命令可查看进程：
  ```bash
  ps aux | grep nginx
  ```
- Master进程负责管理Worker进程，Worker进程数量通常设为CPU核心数，可灵活调整；
- 每个Worker进程可处理的连接数理论最大值为65535，且连接与线程存在本质区别。

##### （2）异步非阻塞IO与事件驱动模式
- **概念对比**：
  - 同步阻塞模式：服务器处理动态请求（如调用PHP-FPM）时，线程需等待处理结果，期间无法对接其他请求；
  - 异步非阻塞模式：服务器遇到耗时操作时，会将任务标记后交给内核缓冲区，继续处理新请求，待内核通知任务完成后，再返回结果给客户端。
- **与Apache的差异**：Apache的事件模式需将请求上下文交给专门线程，存在上下文切换；Nginx全程由同一Worker进程处理请求，仅通过内核监听结果，无上下文切换，效率更高。

##### （3）硬件与性能优化
- 当Nginx性能达瓶颈（如并发量到3万），可通过升级CPU（增加核心数、更换高性能CPU）提升性能；
- 而Apache性能达瓶颈（如并发量1万）时，更多需更换服务。

### （二）Nginx核心功能与应用
#### 1. 反向代理
- **概念**：代理后端服务器，隐藏服务器信息，保护后端服务。客户端仅与Nginx交互，Nginx将请求转发给后端服务器（如Apache）处理，再将结果返回客户端。
- **应用场景**：当后端服务器（如Apache）无法承接高并发请求时，Nginx先接收大量客户端请求，再分发至后端服务器，提升整体服务承载能力。

#### 2. 负载均衡
当单一后端服务器无法处理请求时，可部署多台后端服务器，Nginx通过负载均衡算法（如轮询）将请求均匀分配至不同服务器，避免部分服务器过载，保证服务稳定。

#### 3. 动静分离
通过`location`配置实现，静态资源（如HTML、CSS）由Nginx直接返回，动态资源（如PHP页面）转发给后端服务（如PHP-FPM）处理，充分发挥Nginx处理静态资源的高效性。

### （三）Nginx配置文件核心结构与配置
#### 1. 整体结构
- 最外层为`http`块，包含公共配置（如MIME类型、日志格式、长连接设置等），`http`块内可包含多个`Server`块，每个`Server`块对应一个虚拟主机（类似Apache的虚拟主机）；
- `Server`块内可包含多个`location`块，用于匹配客户端访问的资源路径，不同`location`对应不同处理逻辑。

#### 2. 关键配置项
##### （1）HTTP层公共配置
```nginx
include mime.types;  # 引入MIME类型
default_type application/octet-stream;  # 默认数据流类型
log_format main '$remote_addr - $remote_user [$time_local] "$request" '
                '$status $body_bytes_sent "$http_referer" '
                '"$http_user_agent" "$http_x_forwarded_for"';  # 日志格式定义
keepalive_timeout 65;  # HTTP 1.1及以上长连接超时时间
sendfile on;  # 开启零拷贝技术，提升文件传输效率
```

##### （2）Server层配置
```nginx
listen 80;  # 监听IP和端口，未指定IP则监听所有IP
server_name www.xxx.com;  # 域名配置
```

##### （3）Location层配置
通过匹配规则（如精确匹配`=`、正则匹配`~`、字符串匹配`/`）指定资源处理方式，示例：
```nginx
# 精确匹配，优先级最高
location = /index.html {
    root /usr/share/nginx/html;
}
# 正则匹配，优先级次之
location ~ \.php$ {
    proxy_pass http://backend;  # 反向代理至后端服务
}
# 字符串匹配，路径越长优先级越高
location /static {
    root /usr/share/nginx;  # 指定静态资源根目录
}
```

#### 3. Location匹配优先级
精确匹配（`=`）> 正则匹配（`~`）> 字符串匹配（路径越长优先级越高）。

### （四）Nginx性能优化技术
#### 1. 零拷贝技术（sendfile）
- 传统文件传输需经过“硬盘→内核缓冲区→用户态缓冲区→Socket缓冲区→网卡”多步拷贝；
- 开启`sendfile`后，数据直接从内核缓冲区传输至Socket缓冲区，减少用户态与内核态之间的数据拷贝，提升传输效率。

#### 2. TCP参数优化
```nginx
tcp_nopush on;  # 合并数据包，减少网络拥堵，满负载时一次性推送数据
tcp_nodelay on;  # 禁用延迟，实时场景下（如即时通讯）即使是小包也立即发送，避免等待
```

### （五）Nginx服务管理与监控
#### 1. 状态统计模块
通过配置开启状态统计：
```nginx
location /status {
    stub_status on;
}
```
访问`http://IP/status`可查看活跃连接数、已处理连接数、已处理请求数、正在读/写/等待的连接数等信息，用于监控服务运行状态。

#### 2. 服务启停与重载说明
- **冷重启**：先停止服务再启动（`nginx -s stop && nginx`），期间服务会短暂中断，适用于服务无运行请求时；
- **热重载（reload）**：`nginx -s reload`，在不中断服务的情况下重新加载配置文件。原理是先关闭空闲Worker进程，加载新配置启动新Worker进程，正在处理请求的Worker进程处理完后再加载新配置，保证服务不中断；
- **配置检查**：修改配置后需先执行`nginx -t`检查语法，无错误再执行热重载，避免因配置错误导致服务异常。

### （六）Nginx与Apache的核心区别
| 对比维度   | Nginx                                       | Apache                            |
| ------ | ------------------------------------------- | --------------------------------- |
| 模块加载方式 | 静态加载，编译时将模块源代码与服务一起加载，后续无需额外处理模块            | 动态加载，使用时才加载模块                     |
| 核心功能   | 轻量级HTTP服务器，支持反向代理、负载均衡，具备Apache所有功能且额外有代理能力 | 功能较全，但无反向代理核心能力                   |
| 并发处理   | 基于异步非阻塞IO，无上下文切换，高并发处理能力强（优化后可达3-5万并发）      | 存在上下文切换，高并发场景下效率较低（通常约1万并发）       |
| 性能优化   | 可通过硬件升级（如增加CPU核心数）提升性能上限                    | 性能上限较低，硬件升级效果有限                   |
| 配置文件特性 | 配置文件单一，所有功能集中管理                             | 配置文件分三类（主配置、子配置、`.htaccess`），分工明确 |
