# 视频主要内容总结
## 一、DNF与YUM包管理核心概念
1. **DNF/YUM的核心作用**：二者均基于RPM包进行安装，核心优势是自动解决RPM包的依赖关系，而依赖关系的解决依赖于“仓库”（或“源”）——仓库需同时包含RPM包文件和依赖关系数据，支持本地目录或网络地址两种形式。
2. **仓库配置文件基础**：系统默认仓库配置文件存于`/etc/yum.repos.d/`路径下，且需以`.repo`为后缀才能被DNF/YUM识别。以Rocky系统为例，默认生效的仓库为`AppStream`和`BaseOS`，其配置文件（如`rocky.repo`）包含关键信息：
    - **仓库名称**：置于中括号内（如`[BaseOS]`），是安装过程中显示的仓库标识。
    - **镜像/地址配置**：`mirrorlist`（支持多个网络地址）或`baseurl`（可填网络地址或本地目录，本地需用`file://`格式），用于指定RPM包和依赖的获取来源。
    - **启用状态**：`enabled=1`表示启用仓库，`enabled=0`表示禁用；`gpgcheck=1`启用GPG安全验证（需通过`gpgkey`指定密钥文件路径，默认路径文件已存在）。


## 二、仓库类型配置实操
### （一）网络仓库（默认）
1. **默认机制**：系统安装后默认使用官方网络仓库（如Rocky的`https://mirrors.rockylinux.org/`），配置文件中`baseurl`或`mirrorlist`指向官方网址，安装时自动从网络下载RPM包及依赖。
2. **验证方式**：查看`/etc/yum.repos.d/`下的`.repo`文件，确认`enabled=1`且地址为官方网络路径，安装时仓库列显示默认仓库名（如`AppStream`）即可验证。

### （二）本地仓库配置
1. **配置原因**：工作中反复使用网络仓库会占用带宽，本地仓库可避免此问题，需基于本地挂载的光盘或目录配置。
2. **配置步骤**：
    - **创建自定义配置文件**：在`/etc/yum.repos.d/`下新建`.repo`文件（如`hf.repo`），需包含仓库名称（建议与默认区分，如`[appstream-r9.4-hf]`）、`name`（描述信息）、`gpgcheck=1`（启用验证）、`enabled=1`（启用仓库）、`gpgkey`（复制默认密钥路径），关键是`baseurl`指向本地目录（如`file:///media/AppStream`，需注意Linux严格区分大小写）。
    - **禁用默认网络仓库**：通过三种方式实现：删除默认`.repo`文件（不推荐，后续无法恢复）、修改默认文件后缀（如改为`.repo.bak`）、将默认文件移动到其他目录（如`/etc/yum.repos.d/backup.d/`）。
    - **清空缓存并验证**：执行`dnf clean all`清空原有缓存，再通过`dnf install`（如安装`vim`）测试，若仓库列显示自定义名称，则本地仓库配置成功。


## 三、DNF常用命令与进阶操作
1. **基础命令**：
    - **安装**：`dnf install <包名>`（需手动确认）或`dnf -y install <包名>`（默认确认）；支持通配符（如`dnf -y install bash-completion*`），安装`bash-completion`后重新登录可实现命令选项补全。
    - **软件组安装**：`dnf group install "<软件组名>"`（需加双引号确保识别为整体），适用于安装大量关联包（如图形化环境`"Server with GUI"`，需安装数百个包）。
    - **卸载与升级**：`dnf remove <包名>`（卸载）、`dnf update <包名>`（升级指定包），升级内核需执行`dnf -y update kernel`（作业要求：联网恢复快照后执行，完成后关机做快照）。
2. **查询命令**：
    - `dnf list`：查看所有可安装包，通过最后一列仓库名确认当前使用的仓库类型（本地/网络）。
    - `dnf info <包名>`：查看包的详细信息（如描述、版本），与`rpm -qi <包名>`功能类似。
    - `dnf provides <命令/文件路径>`：查询命令或文件所属的安装包（如`dnf provides vim`），7版本后常用。
    - `dnf search <关键词>`：根据包名或描述中的关键词查询（如`dnf search rz`），7版本前更常用。
3. **缓存管理**：`dnf clean all`清空缓存，`dnf makecache`手动创建缓存，后续安装会自动生成缓存，无强制执行要求，但建议配置仓库后清空缓存。


## 四、常见问题与解决方案
1. **安装进程冲突**：系统中同一时间只能有一个DNF/YUM安装进程运行，多用户同时安装时，后执行的进程会等待前一进程结束（可通过`ps -ef | grep dnf`查看进程，等待或结束前一进程）。
2. **开机检测更新导致安装报错**：7版本系统开机可能触发`packagekit`进程检测更新，此时安装会报错，解决方案：等待检测完成、重启系统、执行`kill <进程号>`结束`packagekit`进程，或长期关闭开机检测更新功能。
3. **配置文件语法错误**：如`enabled=o`（误将数字0写为字母o）导致仓库不生效，需注意区分数字0/1与字母o/l，建议复制默认配置文件中的关键字段（如`gpgkey`路径）避免手动输入错误。
