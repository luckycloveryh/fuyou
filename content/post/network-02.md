## 一、脚本变量取值基础
### （一）变量直接取值的场景
#### 1. 算数运算环境
在算数运算场景下，可直接使用变量本身替代其值，无需额外符号修饰。
示例：
```bash
# 定义变量
N1=10
N2=20
# 直接使用变量进行算数运算定义求和变量
sum=$((N1+N2)) 
# 输出求和结果，sum变量会自动取值计算，结果为30
echo $sum 
# for循环中直接使用循环变量i取值
for ((i=0; i<=10; i++)); do echo $i; done
```
注：字符串区域（双引号、单引号内）和数组区域中，变量前的符号不可省略，需遵循对应语法规则。

#### 2. AWK工具中的变量使用
AWK工具中仅取列操作需使用特定符号（如`$1`表示第一列），自定义变量或内置变量无需额外加符号，可直接使用。
示例：
```bash
# AWK中定义自定义变量"和"并直接取值运算，输出结果为2
echo "" | awk '{和=1+1; print 和}'
# AWK内置变量NR（行号）直接使用，输出当前行号1
echo "test" | awk '{print NR}'
```
注：不同开发者编写脚本的习惯存在差异，遇到不熟悉的变量使用方式时，可结合语法规则推理解决。

## 二、SSH服务核心基础
### （一）SSH服务优势
SSH是安全的远程连接服务，核心优势体现在**身份验证**和**数据加密**：
- 传输安全性：数据传输过程中以密文形式存在，抓包无法直接获取密码等关键信息；
- 对比其他工具：部分远程连接工具（如connect）可能以明文形式传输数据，安全性远低于SSH。

### （二）SSH加密方式
#### 1. 对称加密
- 原理：加密算法与解密算法完全相同，操作简单、便捷；
- 示例场景：文件压缩与解压、摩斯密码等；
- 缺陷：加密算法一旦泄露，整个加密体系会完全暴露，安全性较低。

#### 2. 非对称加密
- 原理：加密算法与解密算法不同，配套生成**公钥**和**私钥**一对密钥：
  - 公钥：可公开传播，用于加密数据；
  - 私钥：需由使用者自行妥善保管，用于解密对应公钥加密的数据；
- 优势：安全性远高于对称加密；
- 缺陷：操作流程相对复杂。

### （三）SSH两种登录验证方式
![img](https://cdn.jsdelivr.net/gh/luckycloveryh/picgo-bed@main/images/obsidian/network-02/01.png)
#### 1. 密码验证
##### （1）完整流程
① 客户端向服务器发起SSH连接请求；
② 服务器向客户端发送自身公钥，客户端验证公钥（公网可查询公网信息对比，局域网可直接在服务器端查看对比，防止中间人攻击）；
③ 验证通过后，客户端与服务器协商生成一个对称的会话密钥；
④ 若客户端此前未存储过该服务器信息，需手动点击“yes”接收服务器信息；若已存储，可直接输入用户名和密码；
⑤ 客户端使用会话密钥加密用户名和密码，发送至服务器；
⑥ 服务器通过会话密钥解密，将解密后的用户信息与`/etc/passwd`等系统文件中的信息对比，验证用户存在且密码正确后，登录成功。

##### （2）相关文件
服务器的公钥等信息会存储在客户端的指定文件中：
- Linux系统：当前用户家目录下的`~/.ssh/known_hosts`文件；
- Windows系统：通常存储在SSH连接工具（如Xshell）的主机密钥管理者中。

#### 2. 密钥验证（免密登录）
![img](https://cdn.jsdelivr.net/gh/luckycloveryh/picgo-bed@main/images/obsidian/network-02/02.png)
##### （1）密钥生成（客户端操作）
使用`ssh-keygen`命令生成非对称密钥对，可指定算法、密钥长度等参数。
```bash
# 生成RSA算法的密钥对，密钥长度设置为2048位（最小要求）
ssh-keygen -t rsa -b 2048
```
参数解释：
- `-t rsa`：指定密钥生成算法为RSA（也可选择其他算法）；
- `-b 2048`：指定密钥长度为2048比特（可根据需求增加，如4096位，安全性更高）；
- 执行命令后按回车，可选择：
  - 密钥保存路径：默认存储在当前用户家目录下的`~/.ssh/`目录；
  - 私钥保护密码：为实现免密登录，通常直接回车设为空（若设置密码，每次免密登录仍需输入该密码）。
生成结果：`~/.ssh/`目录下会生成两个文件——`id_rsa`（私钥，需妥善保管）、`id_rsa.pub`（公钥，可公开）。

##### （2）公钥传输（客户端向服务器发送）
使用`ssh-copy-id`命令将客户端公钥发送到服务器指定用户的`~/.ssh/authorized_keys`文件中。
```bash
# 向服务器root用户发送公钥（基础用法）
ssh-copy-id root@192.168.66.2
# 向服务器普通用户（如李四）发送公钥
ssh-copy-id 李四@192.168.66.2
```
参数/流程解释：
- `root@192.168.66.2`：指定服务器的登录用户名和IP地址；
- 首次传输时，需先接受服务器的公钥（类似密码验证中接收服务器信息的步骤）；
- 执行命令后需输入服务器对应用户的密码，验证通过后，客户端公钥会被写入服务器该用户的`~/.ssh/authorized_keys`文件。

##### （3）免密登录流程
① 客户端向服务器发起SSH请求，自动携带自身公钥信息；
② 服务器在`authorized_keys`文件中查找该公钥，若存在则生成随机字符串，并用该公钥加密后发送给客户端；
③ 客户端使用本地私钥解密得到随机字符串，再用服务器公钥加密后回传给服务器；
④ 服务器使用自身私钥解密，对比解密后的字符串与此前生成的字符串，一致则验证通过，登录成功（无需输入密码）。

##### （4）单向性规则
密钥验证默认是单向的：若客户端A对服务器B配置免密登录后，服务器B无法直接免密登录客户端A；若需双向免密，需在A、B双方分别执行“密钥生成+公钥传输”操作。

## 三、SSH免密登录特殊场景处理
### 1. 多用户免密配置
需将客户端公钥发送到服务器对应普通用户的`~/.ssh/authorized_keys`文件，而非root用户。
```bash
# 向服务器的李四用户发送公钥，实现对该用户的免密登录
ssh-copy-id 李四@192.168.66.2
```
流程解释：
- 执行命令后需输入李四用户的密码；
- 验证通过后，客户端公钥会写入服务器李四用户的`~/.ssh/authorized_keys`文件，后续客户端可免密登录服务器的李四用户。

### 2. 缺省用户名规则
使用`ssh`登录或`ssh-copy-id`传输公钥时，若未指定用户名，默认使用客户端当前登录的用户名。
```bash
# 客户端当前登录用户为root，未指定用户名，默认以root登录服务器
ssh 192.168.66.2
# 客户端当前登录用户为李四，未指定用户名，默认以李四用户传输公钥
ssh-copy-id 192.168.66.2
```

### 3. 多网卡服务器免密配置
服务器若有多个网卡（如IP：192.168.66.2、192.168.246.128），对其中一个IP配置免密后，对另一IP免密需满足：
① 确保客户端与目标IP网络可达（可通过设置网关实现）；
② 首次登录目标IP时，手动接受服务器公钥（因`known_hosts`文件中无该IP对应的服务器信息）；
③ 因服务器`authorized_keys`文件已存储客户端公钥，接受公钥后即可免密登录。

### 4. 服务器IP变更后的免密处理
服务器IP从192.168.66.2变更为192.168.66.22后：
① 客户端首次登录新IP时，需接受服务器新的公钥（`known_hosts`文件中仅存储旧IP的服务器信息）；
② 服务器`authorized_keys`文件仍保留客户端公钥，接受新公钥后可继续免密登录。

## 四、SSH服务安全保护措施
### 1. 禁止root远程登录
修改服务器端SSH配置文件，禁用root用户远程登录，需重启SSH服务生效。
```bash
# 方式1：修改主配置文件
vim /etc/ssh/sshd_config
# 在文件中修改/添加：PermitRootLogin no

# 方式2：修改细分配置文件（部分系统）
vim /etc/ssh/sshd_config.d/01-permit-root-login.conf
# 在文件中添加：PermitRootLogin no

# 重启SSH服务使配置生效
systemctl restart sshd
```
参数/效果解释：
- `PermitRootLogin no`：禁止root用户通过SSH远程登录；
- 生效后需通过普通用户登录服务器，再通过`sudo`等方式提升权限操作。

### 2. 禁止密码登录
仅保留密钥验证方式，需先确保已配置免密登录，再修改配置并重启服务。
```bash
# 编辑SSH主配置文件
vim /etc/ssh/sshd_config
# 修改参数：PasswordAuthentication no

# 重启SSH服务
systemctl restart sshd
```
参数/注意事项：
- `PasswordAuthentication no`：禁用密码登录方式；
- 若未提前配置免密登录，修改后会导致无法登录服务器。

### 3. 限制监听IP
修改SSH服务的监听IP，仅允许指定IP接收SSH连接请求。
```bash
# 编辑SSH主配置文件
vim /etc/ssh/sshd_config
# 修改ListenAddress参数（默认0.0.0.0，监听所有IP）
ListenAddress 192.168.66.2

# 重启SSH服务
systemctl restart sshd
```
参数/效果解释：
- `ListenAddress 192.168.66.2`：仅监听服务器内网IP 192.168.66.2；
- 生效后仅能通过该IP连接SSH服务，其他IP无法访问。

### 4. 修改监听端口
默认SSH监听22端口，修改为自定义端口（需确保端口未被占用）。
```bash
# 编辑SSH主配置文件
vim /etc/ssh/sshd_config
# 修改Port参数（示例改为2509）
Port 2509

# 重启SSH服务
systemctl restart sshd

# 客户端登录时需指定新端口
ssh -p 2509 root@192.168.66.2
```
参数/注意事项：
- `Port 2509`：将SSH监听端口改为2509（端口范围1-65535）；
- 客户端登录命令中`-p 2509`：指定连接的SSH端口为2509；
- 第三方工具（如Xshell）需在连接设置中手动指定新端口。

### 5. 辅助保护手段
#### （1）防火墙限制SSH端口访问
仅允许指定IP访问SSH端口（以22端口为例，若修改端口则替换为新端口）。
```bash
# 以firewalld为例，允许192.168.66.100访问22端口
firewall-cmd --permanent --add-rich-rule='rule family="ipv4" source address="192.168.66.100" port protocol="tcp" port="22" accept'
# 重新加载防火墙规则
firewall-cmd --reload
```
效果解释：仅IP为192.168.66.100的客户端可访问服务器的SSH 22端口。

#### （2）fail2ban工具防暴力破解
通过监控SSH日志，封禁多次登录失败的IP：
```bash
# 安装fail2ban（CentOS系统）
yum -y install fail2ban
# 启动并设置开机自启
systemctl start fail2ban
systemctl enable fail2ban
```
效果解释：fail2ban会实时监控SSH登录日志，当某IP多次登录失败时，会自动通过防火墙封禁该IP，防止暴力破解。

## 五、SSH相关文件传输命令与工具
### （一）SCP命令（远程文件复制）
基于SSH实现客户端与服务器间的文件远程复制，验证方式与SSH一致（免密则无需输密码）。
#### 1. 客户端→服务器（上传文件）
```bash
# 基础用法：指定用户名、服务器IP和目标路径
scp /root/194.txt root@192.168.66.2:/root/
# 简化用法：客户端当前用户为root，省略用户名
scp /root/194.txt 192.168.66.2:/root/
```
参数/解释：
- `/root/194.txt`：客户端待复制的文件路径；
- `root@192.168.66.2`：服务器登录用户名和IP；
- `/root/`：服务器目标存储路径。

#### 2. 服务器→客户端（下载文件）
```bash
# 指定用户名、服务器文件路径和客户端目标路径
scp root@192.168.66.2:/root/194.txt /root/
```
参数/解释：
- `root@192.168.66.2:/root/194.txt`：服务器文件路径；
- `/root/`：客户端目标存储路径。

### （二）SFTP协议与命令（安全文件传输）
SSH附属功能，支持交互式文件传输操作，免密状态下无需输密码。
#### 1. 连接服务器
```bash
# 连接服务器root用户
sftp root@192.168.66.2
```
效果：连接成功后默认进入服务器root用户的家目录，进入SFTP交互式界面。

#### 2. 下载文件
```bash
# 基础用法：下载服务器文件到客户端当前目录
get /root/194.txt
# 指定客户端目标路径
get /root/194.txt /home/李四/
```
参数/解释：
- `get`：SFTP的下载命令；
- `/root/194.txt`：服务器文件路径；
- `/home/李四/`：客户端目标存储路径。

#### 3. 上传文件
```bash
# 基础用法：上传客户端文件到服务器当前目录
put /root/200.txt
# 指定服务器目标路径
put /root/200.txt /home/李四/
```
参数/解释：
- `put`：SFTP的上传命令；
- `/root/200.txt`：客户端文件路径；
- `/home/李四/`：服务器目标存储路径。

#### 4. 查看SFTP支持的命令
```bash
# 在SFTP交互式界面输入
?
```
效果：列出所有SFTP支持的命令（如`ls`、`cd`、`rm`等）。

### （三）其他文件传输工具
#### 1. Xshell自带SFTP（图形化操作）
① 打开Xshell并连接目标服务器；
② 点击界面中的黄色下载按钮（或对应SFTP按钮），取消其他FTP工具推荐；
③ 进入Xshell内置SFTP界面，支持拖拽文件实现上传/下载（无需命令，图形化操作）。

#### 2. LRZSZ工具（命令行交互式传输）
需先在服务器端安装工具，再通过客户端命令操作。
```bash
# 服务器端安装LRZSZ（CentOS系统）
yum -y install lrzsz

# 客户端上传文件到服务器
rz
# 客户端下载服务器文件
sz /root/194.txt
```
参数/流程解释：
- `rz`：执行后弹出文件选择窗口，选择客户端本地文件即可上传至服务器当前目录；
- `sz /root/194.txt`：执行后弹出路径选择窗口，选择客户端存储路径，即可将服务器的`/root/194.txt`下载到客户端。

## 六、SSH实操练习任务
要求：4台同一局域网（连接同一交换机）的机器，实现互相免密登录（含每台机器对自身的免密登录）。

### 1. 手动操作方式
每台机器需对其他3台机器（含自身）执行“密钥生成+公钥传输”操作，总计需执行`4×4=16`次操作。
核心步骤（单台机器对另一台的操作示例）：
```bash
# 1. 生成密钥对（若未生成）
ssh-keygen -t rsa -b 2048
# 2. 向目标机器（如192.168.66.3）的root用户传输公钥
ssh-copy-id root@192.168.66.3
# 3. 对自身免密登录（传输公钥到本地）
ssh-copy-id root@localhost
```

### 2. 脚本实现方式
编写自动化脚本，批量完成“密钥生成+公钥分发”，减少手动操作量。
核心思路：
① 脚本中定义所有目标机器的IP和用户名列表；
② 循环遍历列表，自动生成密钥（跳过已生成的情况）；
③ 自动传输公钥到每台目标机器（含自身）；
④ 利用免密登录原理，在每台机器上存储所有其他机器的公钥，简化互信配置。
示例脚本框架（可根据实际需求完善）：
```bash
#!/bin/bash
# 定义目标机器列表（IP+用户名，示例为4台机器）
HOSTS=("root@192.168.66.2" "root@192.168.66.3" "root@192.168.66.4" "root@192.168.66.5")

# 生成密钥对（若不存在）
if [ ! -f ~/.ssh/id_rsa ]; then
    ssh-keygen -t rsa -b 2048 -N "" -f ~/.ssh/id_rsa
fi

# 循环分发公钥到所有目标机器
for host in "${HOSTS[@]}"; do
    ssh-copy-id -o StrictHostKeyChecking=no $host
done
```
脚本参数解释：
- `HOSTS`：数组定义4台机器的登录信息；
- `ssh-keygen -N "" -f ~/.ssh/id_rsa`：无密码生成密钥对，指定存储路径；
- `ssh-copy-id -o StrictHostKeyChecking=no $host`：自动接受服务器公钥，无需手动确认，批量分发公钥。

## 补充：SSH服务的实际应用
可通过SSH实现远程服务器监控与操作，示例：
```bash
# 远程检查服务器Apache服务状态
ssh root@192.168.66.2 "systemctl status httpd"

# 若Apache服务未运行，远程启动
ssh root@192.168.66.2 "systemctl start httpd"
```
效果解释：直接通过`ssh 用户名@服务器IP "操作命令"`的形式，在本地执行远程服务器的命令，无需手动登录服务器。
